# 高并发 / 性能 / 可观测性检查清单

> 本项目是**桌面单机工具**（无服务端、无多租户）。
> 下表区分「适用」与「不适用」，不适用项写明原因，不硬套。

## 适用（本项目的真实并发面）

| 面 | 现状 | 检查点 |
|----|------|--------|
| 批量克隆并发 | 线程池 ≤32 + 流控 64 惰性补投 | 是否随失败率自适应降级？失败是否分类（网络/认证/平台限制/本地）？ |
| 写盘互斥 | `cross_process_lock`（线程锁 + msvcrt/fcntl） | 是否**跨进程**？锁失败是否关闭句柄再降级？是否留痕？ |
| DB 并发 | 单线程写 + `BEGIN IMMEDIATE` + `busy_timeout=30000` | 是否有 N+1？是否无 LIMIT？ |
| 幂等 | Webhook 600s 去重（进程内） | 「查重+占位」是否在同一临界区？失败是否撤销占位？ |
| 审计写盘 | `notify.log` 追加 + 独立写锁 | 并发 append 是否原子（Windows 非原子，必须加锁）？是否滚动？ |
| 启动性能 | 启动耗时自检留痕 | 冷启动是否阻塞 UI？ |
| UI 线程 | worker 只 emit，槽回主线程 | 是否有工作线程直接碰控件？ |

## 不适用（写清原因）

| 项 | 原因 |
|----|------|
| Load Balancer / CDN | 单机桌面应用，无服务端分发 |
| Redis / Cache Aside | 无共享缓存；本地 SQLite + 内存缓存已足够 |
| DB Replication / Sharding | 单机 SQLite，无横向扩展需求 |
| Kafka / RabbitMQ | 无跨进程消息总线；本地任务队列即可 |
| Rate Limiting（对外接口） | 仅本地回环 HTTP / stdio MCP，无公网入口 |
| Circuit Breaker | 无多服务依赖；git 失败已有分类降级与重试队列 |
| Metrics/Traces | 桌面端以结构化日志（`app.log`）为主；无集中采集 |

## 压测方法（本项目已验证）
- **幂等**：40 线程 + `threading.Barrier` 同时起跑、同 payload；断言「真正发送 1 次」。
  连跑 30 次必须全绿。
- **并发写**：8 线程 × 12s 全速 `settings.save`；断言零失败、无残留 tmp。
- **跨进程锁**：两个真子进程 + 启动屏障；含**无锁对照组**反向自检。

## 可观测性（现状）
`data/app.log`（结构化）、`data/error.log`（全局兜底 + 崩溃栈）、
`data/notify.log`（通知审计，只记 `scheme://host`）。

## 压测红线
禁止对生产/线上环境压测；只用本地或 CI。
