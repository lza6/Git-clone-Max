# 全项目终局审计 SOP

## 0. 先读
`.agent/memory/` 全部；`CLAUDE.md` §0（权威文档位置）。

## 1. 事实基线
仓库结构 / 依赖 / 构建 / 启动 / 测试 / 部署 / 分支状态 / CI / 文档 / 技能。

## 2. 需求追踪矩阵
把上下文里的需求逐条映射到「实现位置 + 状态 + 证据 + 缺口」。
**无法映射到真实实现或真实验证的，一律视为未闭环。**

## 3. 反向审计（先攻击自己）
1. 是否偷换需求？2. 浅实现当完整？3. 只修表面没打通链路？
4. 漏了用户路径中的按钮/状态/异常？5. 漏了调用方踩坑点？
6. 改一个点破坏别的？7. 默认环境天然存在？8. 没更新文档？
9. 无证据就宣称完成？10. 漏了用户第一时间会遇到的问题？

## 4. 并行审计（子代理）
- `explorer`：台账复验、接缝、契约、安全、盲点
- `worker`：修复
- `verifier`：只读复验
- `reviewer`：对抗式代码审查
禁止同一文件被多代理同时改。

## 5. 分级修复
P0（不可用/数据破坏/安全）→ P1（主流程/契约/回归）→ P2（体验/文档）→ P3（建议）。
每项记：改了什么、为什么、影响面、验证、回滚。

## 6. 真实验证
用 `verification-matrix.md`。**必须真跑**，贴命令+输出；未跑写「未验证」。

## 7. 文档与报告
`README` / `CLAUDE.md` / `docs/*` / changelog / HTML 报告（含测验）。

## 8. 诚实结案
只基于证据回答：哪些已闭环 / 部分 / 受阻 / 风险。

## 常见坑
- 台账「全部闭环」不可信 —— 必须逐条复验（本项目 `计划书/` 就翻过车；
  墓碑与审计结论在 `docs/archive/plans/20261017/archive-manifest.md`，流程见 `plan-doc-audit.md`）。
- 「本机绿 CI 红」先做干净检出对照。
- 崩溃点漂移 = 竞态，按系统性成因处理。
- 涉及远端状态先 `fetch`。
