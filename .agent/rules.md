# .agent/rules.md — 本项目 AI 协作铁律（先读）

> 冲突时优先级：安全/授权边界 > 用户本轮目标 > 本文件 > 其他文档。

## 0. 开工前（强制）

1. **先读** `.agent/memory/`：
   - `tested-scope.md`（哪些验证已跑过，避免重复）
   - `known-issues.md`（已知边界，别当 bug 修）
   - `decisions.md`（为什么这样做，别推翻后重犯）
   - `change-index.md`（改这块有哪些连带影响）
2. **判断是否过时**：与代码冲突时**以代码为准**，并顺手修正文档。
3. **再读实际代码**，不要凭记忆或文档直接改。
4. 项目级权威文档位置见仓库根 `CLAUDE.md` §0。

## 1. 编码前（强制先思考）

用 `<thinking>` 完成：目标、范围、关键假设、验证方式、可能踩的坑。
多种解读时全部列出，不沉默选择。

## 2. 验收标准（缺一不可）

- 改了 `gcm/` → `ruff check gcm` + `mypy gcm`
- 改了行为 → 跑 `tested-scope.md` 里对应的**定向回归**
- 改了测试面/覆盖率 → 跑快集全量
- 声称"完成"必须附：命令 + 真实输出摘要
- 未运行的验证必须写"未验证"及原因

## 3. 禁止假闭环（本轮的血泪账）

- **守卫必须覆盖生产路径**：`TestG69_18NoMainWindowRefCycle` 曾因不调 `show()`
  而永远绿，而真实用户永远会 `show()`。
- **断言必须能失败**：不要 `assertTrue(True)`；计数类断言要写精确值
  （`assertIn("2", text)` 在「1 和 2 互换」时仍通过）。
- **静态守卫不要被自己的注释骗**：僵尸字段守卫曾用文本匹配，
  被 changelog 里的字段名喂成假绿 → 改 AST。
- **验证"改色/改配置"要真的读出来**：`_dim_color` 查的键名不存在，
  改了等于没改。

## 4. 兼容与回滚

- 改持久化格式（`settings.json` / `progress.json`）必须考虑旧数据；
  用 `_DEFAULTS` 过滤未知键，并提供**历史值不丢**的路径。
- 改 Qt 信号签名 / 设置字段前，grep 全库调用点。
- 每个不可逆操作先留回滚点（tag / 备份 / 还原命令）。

## 5. 复用优先

- 先搜项目内已有实现（`docs/code-gems.md`），禁止重复造轮子。
- 新增 UI 逻辑**一律落独立模块**，不得再往 `main_window.py` 里塞。
- **一个映射只留一处**（2026-11-01 v9.12.0 实测）：`settings → 消费方` 的参数映射只允许存在于
  唯一工厂（如 `ui/engine_factory.build_sync_engine`）。发现第二份（如 `MainWindow.__init__` 里手写的
  参数表）**删掉它**，不要"两边都补一下" —— 两份必然漂移，而单测只会覆盖它碰巧走过的那一份。
- **新参数必须有生效断言**：`Xxx(arg=非默认值)` → `assert obj.attr == 非默认值`。
  否则它随时会被后人在同一函数后半段覆盖掉而无人发现（"可配置性伪装"）。

## 6. 审查

- 改完代码必须走独立审查（只读、不修改），关注：需求完整性、逻辑、
  边界、质量、测试覆盖、**实际运行结果**。
- 审查最多 3 轮；无实质进展则记录阻塞。

## 7. 文档

- 用户可见新文案走 `tr()`，键必须同时进 `zh.py` / `en.py`。
  **用户可见文本里不得出现 Markdown 标记**（`QLabel`/`QMessageBox` 是纯文本，`**` 会显示成星号）——
  有守卫 `TestNoMarkdownInUserFacingText`。
- 版本号只来自 `gcm.__version__`。
- 改了行为 → 同步 `README` / `docs/agent-contract.md` / `changelog`。
- **数字必须与实测一致**：改模块行数/超长函数/测试文件数/技能包数后跑
  `python scripts/doc_drift_check.py`，必须 `DRIFT 0`（这是 DoD 的一部分）。
- **计划文档**：含未闭环项的计划文档一律**不删**；要归档先按
  `.agent/skills/plan-doc-audit.md` 走（manifest + 逐条状态），"全部闭环"这句话不构成证据。

## 8. 审计与守卫的自身可信度

- **守卫要用 AST，不用文本匹配**（会被自己的注释/changelog 喂成假绿）。
  **审计脚本自身也适用**：v9.12.0 的闭环抽查就因为文本匹配命中了"注释里对修复的描述"而误报。
- **新增守卫必须先证明它会红**（把缺陷造回去，它必须红并点名该缺陷）；用 `skipTest` 兜空等于没写。
- **视觉验收不能只截图**：`ui_screenshot_audit.py` 只存图不断言，按钮裁切躲过了 4 轮迭代。
  关键控件要加 `visibleRegion == rect` 的几何断言。
- **跨重启路径要单独验**：批次路径与启动期路径是两条，只测前者会漏掉后者的接线缺失。
