## 三、v6.0 升级范围声明（R 表示必须，A 表示增强，O 表示可选）

```
R = Required    根因/主流程缺陷，不修不配发版
A = Advanced    显著提升体验或能力，推荐落地
O = Optional    锦上添花，按剩余精力取舍
```

- **R 类**（约 20 条）：进度表搜索/排序、单仓库暂停/继续、多平台直克隆补全、URL 历史与记忆、token 加密存储、错误日志兜底、single-instance、崩溃自检、日志增量导出、重复导入去重等。
- **A 类**（约 50 条）：仓库统计页、标签/分组、搜索过滤、黑名单、剪贴板监听、多主题、代理自动检测、浅克隆增强（treeless/bundle）、submodule、指定 tag、镜像源、统计报表导出、自动更新落地、UI 打磨等。
- **O 类**（约 30 条）：i18n、Portable 模式、多账号 SSH、发布签名、CI 打包、Reddit 式热键等。

> 完整清单以《下一步改进指南.md》为准，编号稳定、可单独验收。

## 四、执行规约（实施方必须遵守）

1. **文档优先，分里程碑落地**：按 G01→G12 模块顺序分批，每批一个里程碑，跑通全量测试再进下一批，**严禁前面改 bug 后面加功能又出新 bug**。
2. **改动边界**：
   - 禁止重写整个文件、推翻现有闭环（engine/worker/db 的并发安全已实测通过，动它必须出回归证据）。
   - 新增能力优先**新文件 + 钩子接入**，旧接口保持向后兼容。
   - 只改必须改的；顺手清理身边死代码并注明。
3. **TDD 前置**：每个改进项先写测试再实现（RED→GREEN→IMPROVE）；目标核心覆盖率 ≥90%；测试命令：
   ```bash
   python -m unittest discover -s tests -v
   python -m coverage run --source=gcm -m unittest discover -s tests
   python -m coverage report
   ```
4. **安全红线**：不得把 token/密钥以明文打印、提交或硬编码；新增网络出口一律校验 URL 协议与主机白名单。
5. **文档同步**：改完任何用户可见行为，同步更新 `README.md` 与本指南对应条目为「✅ 已落地」并记证据。
6. **终止条件**：某里程碑连续 2 次有意义的替代尝试仍阻塞 → 记录阻塞点与最小缺失条件，不伪造完成；P0/P1 未清零前不宣称可发布。

## 五、里程碑路线（建议执行顺序）

| 里程碑 | 聚焦 | 主要模块 | 预估工作量 |
|--------|------|----------|-----------|
| M1 | 可靠性加固 | R 类缺陷（single-instance/崩溃兜底/token 加密/日志兜底/去重） | 中 |
| M2 | 多平台克隆 | G01 多 host 直克隆 + 分布目录 + 测试 | 大 |
| M3 | 核心交互增强 | G02 搜索排序、暂停/继续、URL 历史、导出/导入 | 中 |
| M4 | 仓库管理进阶 | G03 标签分组、黑名单、统计页、详情增强 | 大 |
| M5 | 网络与性能 | G04 代理自动检测、深浅克隆增强、submodule/tag/镜像 | 中 |
| M6 | 体验与工程化 | G05 主题/托盘/i18n/热键/现代化 UI、G06 打包签名 CI、全部收尾 | 大 |

> 每个里程碑结束时：全量测试全绿 + 覆盖率绿线 + 本指南相关条目勾选 = 才可进入下一里程碑。
