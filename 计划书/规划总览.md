## 四、执行规约（实施方必须遵守）

1. **文档优先，分里程碑落地**：按 M0→M7 顺序分批，每批一个里程碑，跑通全量测试再进下一批，**严禁前面改 bug 后面加功能又出新 bug**。
2. **改动边界**：
   - 禁止重写整个文件、推翻现有闭环（engine/worker/repo_db 的并发安全已实测通过，动它必须出回归证据）。
   - 新增能力优先**新文件 + 钩子接入**，旧接口保持向后兼容。
   - 只改必须改的；顺手清理身边死代码并注明。
3. **TDD 前置**：每个改进项先写测试再实现（RED→GREEN→IMPROVE）；目标核心覆盖率 ≥85%（M4 起）；测试命令：
   ```bash
   python -m unittest discover -s tests
   python -m coverage run --source=gcm -m unittest discover -s tests
   python -m coverage report
   ```
4. **安全红线**：不得把 token/密钥以明文打印、提交或在导出中出现；新增网络出口一律校验 URL 协议与主机白名单；付费 API 一律 Mock。
5. **文档同步**：改完任何用户可见行为，同步更新 `README.md` 与本指南对应条目为「✅ 已落地」并记证据。
6. **终止条件**：某里程碑连续 2 次有意义的替代尝试仍阻塞 → 记录阻塞点与最小缺失条件，不伪造完成；P0/P1 未清零前不宣称可发布。
7. **覆盖门禁**：当前实测 TOTAL 82% 与 CI 门禁 82 持平（临界）；M0 修完测试隔离缺陷后复测对齐；M4 冲刺 85% 前不得降。
8. **测试隔离铁律**：新增 UI 测试默认在模块级创建 `QApplication` 单例（见 G50-1），禁止依赖其他测试文件的执行顺序。
