## 0. 使用约定（先读）

- **先思考后编码**：任何改动前，先在规划文档/本轮分析中写"方案 + 根因 + 折衷"，再动手。禁止边改边想。
- **TDD 铁律**：每个功能先列测试清单（用例→失败→实现→转绿→回归→覆盖），测试套件要真实且尽量全覆盖；禁止"改了没验证就声称通过"。
- **强制验证**：必须实际运行 `unittest`、`coverage`、`ruff`、`mypy`、真实 git E2E、打包/冒烟，展示命令与输出作为证据。
- **不重构守则**：本阶段除非有明确验收项，否则**严禁大重构**；小逻辑/小 Bug 可顺手修，但要入测试。
- **文档权威化**：建议逐步建立 `计划书/db_structure.md`（数据库权威）与 `计划书/project_specs.md`（任务权威），改动 schema/路线时同步更新，防止上下文丢失。
- **清理纪律**：升级完成后删除旧产物/临时文件/构建缓存（build/dist 内旧版本、._*.log、测试残留），保持仓库"最新且干净"；删除前先确认路径与归属，避免误删用户数据。

## 2. 第一性原理瓶颈分析

把"GitHub 批量下载/增量更新/入库追踪"拆到本质，判断当前瓶颈：

| 本质诉求 | 现状 | 瓶颈/机会 |
|---|---|---|
| 快（批量、并行、省流量） | 并发 32、弱网降级、镜像、LFS | ① 大仓库失败重试仍偏串行；② 无"智能分片/断点续传下载"（仅 git 协议）；③ 无 CDN/代理池负载均衡 |
| 稳（不丢、不卡、可恢复） | 断点续传、锁、崩溃恢复、健康检查 | ① 长时间大批量无"看门狗续跑"（中断后需手动重跑）；② progress.json 会增长无治理（可加滚动/压缩） |
| 懂（数据可读、可分析、可汇报） | 统计中心、报表 CSV/MD/xlsx、健康分 | ① 健康分单值；② 无"多维评分卡/趋势/阈值告警"；③ 无导出到网盘/API |
| 小白友好/教学 | 帮助对话框、推荐项、置灰 tooltip | ① 无"黑匣子教学化"（小白不知原理/排错）；② 无新手任务引导（onboarding 已有但可深化） |
| 可扩展（agent 化/生态） | CLI、Webhook、技能雏形 | ① 技能未固化交付；② 无 MCP server 暴露能力；③ 无媒体/电商/办公横向能力 |

## 4. TDD 清单与执行顺序（DoD，逐节点）

每个优化项按以下**执行顺序**（先规划 → 分解 → TDD → 落地 → 验收 → 收尾）：

```
0. 读项目结构与既有测试 → 避免重复/冲突
1. 写方案 md（本指南落点）→ 拆任务节点（每个节点：输入/输出/验收）
2. TDD：先写失败测试（单元 → 集成 → E2E）
3. 实现最小可运行代码（禁止 TODO/省略号/散文式延迟）
4. 转绿：运行单个测试 → 相关回归 → 全量
5. 质量闸：coverage ≥ 84（门禁）、ruff 0、mypy 0、真实 git E2E 冒烟
6. 手动体验：运行 scripts/启动Git-clone-Max.bat（真实启动、点按钮、看反馈）；离屏截图登记
7. 收尾：清理临时文件/旧产物；更新 验收清单.md + workflow_status.md
8. 二次审查：自查 diff + 相邻行为；高风险项交独立 Critic 复审
```

**强制验证命令（每节点至少展示其一）**：
- 全量：`python -m coverage run --source=gcm -m unittest discover -s tests && python -m coverage report --fail-under=84`
- 质量：`python -m ruff check gcm && python -m mypy gcm`
- E2E：`python scripts/e2e_smoke.py`；打包冒烟：`python scripts/health_check.py --json dist/health_check.json`

## 8. 安全红线与决策门禁

1. **付费/外部操作**：默认只读；显式开启 + 显式填 URL/token 才发；审计落盘；不越权（呼应参考库 claude-ads 门禁思想）。

3. **数据保护**：不覆盖用户 data/、不强制删除用户数据；git 操作不 -f 推送、不重置、不清理脏工作区。
4. **代码门禁**：coverage ≥84（底盘 ≥82）、ruff 0、mypy 0、E2E 绿、实际产物健康检查通过，方可标记"完成"。
5. **范围门禁**：重大重构/横向扩展（P2 方向）需你确认后再动；本阶段严格执行"先文档→后 TDD→再落地"。
