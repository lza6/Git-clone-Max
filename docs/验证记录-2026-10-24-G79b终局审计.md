## 9. 过程中的真实事故记录（诚实披露）

**现象**：22:50 前后，工作区里 `docs/` 下 **16 个被跟踪文件**（全部为非 ASCII 文件名：`计划书/**`、
`验证记录-*.md`、`慢测定位.md`、`SOP-交付与维护.md`）变成 **删除** 状态。

**影响**：对 **v9.10.2 发布物零影响** —— 构建与发布都取自提交树 `289adf0`，这些文件在 git 里完好。
真正的风险是"没看见就提交"：那会把 16 份文档一起删掉（本项目 2026-10-16 翻过同类车）。

**处置与核验**：

```text
git ls-files -d -z docs/ | xargs -0 git checkout --     # 从 HEAD 恢复
git ls-files -d | wc -l        → 0        # 全仓已无被删文件
git ls-files docs/ | wc -l     → 42       # tracked docs 数量复原
守卫复跑                        → Ran 32 · OK
```

**归因（未确定，但已缩到最小）**：受控实验逐个排除窗口期内的破坏性嫌疑 —— 每个候选跑前跑后都做
`docs/` 文件快照比对：

| 候选 | 结果 |
|------|------|
| `scripts/build_portable_zip.py --check` + `publish_release.py --dry-run` | 42 → 42，零删除 |
| `scripts/health_check.py`（含 `Popen` 拉起 exe 60s + `taskkill /T /F`） | 42 → 42，零删除 |
| `python -m PyInstaller --noconfirm Git-clone-Max.spec`（整轮重跑） | 42 → 42，零删除 |
| 头号嫌疑：本轮并行运行的**只读审计子代理**（其 shell 活动不在主控上下文内） | 无法审计其执行轨迹 |
| **新证据（23:01）**：仓库根出现未跟踪文件 `参考的结果计划指南.md`，内容属**另一项任务**（参考项目对标审计） | 证明同工作区存在**并行会话/代理活动**，与删除时间窗吻合（R-07 风险形态） |

**教训（已写进决策 D32）**：①提交/发布前必看 `git status --porcelain`；②「只读代理」只是提示词约束、
不是权限约束，**不要在同一工作区并行跑多个带 shell 的子代理**；③出现意料之外的 `D` 先恢复再继续。
