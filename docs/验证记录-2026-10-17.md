## 3. CI 红灯的 5 类成因与修法（**改 CI 前务必先读**）

| # | 成因 | 定位手段 | 修法 | 守卫 |
|---|------|---------|------|------|
| 1 | 崩溃时**不打印失败清单** → 80+ 次红灯无法定位 | 拉全量 CI 日志 | `ci_run_fast.py` 逐模块落痕 + 失败逐条点名 + `faulthandler` | 运行器自身输出 |
| 2 | **测试泄漏线程**：`test_git_thread_exit` 用 `sleep(3600)` 卡死 stdout 又断言「线程仍存活」→ `_pump` 僵尸线程活过整个套件 | `faulthandler` C 栈直指 `service.py:255 _pump` | 改 `threading.Event` 放行 + 收尾断言线程真退出 | `TestG69_18NoLeakedPumpThreads` |
| 3 | **Qt 控件由引用环维持** → 自动循环 GC 在 `processEvents()` 中途销毁控件/子定时器 → `activateTimers` 解引用已释放对象 | 对照实验 + `del`/`gc.collect()` 探针 | 整轮关闭循环 GC，结束回收一次 | 见 §4 探针命令 |
| 4 | **MCP 服务在非 UTF-8 控制台崩溃**：`ensure_ascii=False` 写中文到 cp1252 stdout → `UnicodeEncodeError` 打断 JSON-RPC | CI 点名 + 本地 cp1252 复现 | `_force_utf8_streams()`（同 `gcm/cli.py` 守卫） | `TestG69_18AgentSurfaceRobustness` |
| 5 | **CI 自身**：覆盖率摘要步骤（信息性）写中文到 cp1252 → 弄红 job | CI 日志尾部 | 脚本内 reconfigure + `continue-on-error: true` | 无（YAML 审查） |

### 3.1 归因纪律（本轮最重要的方法论）

- **崩溃点随机漂移 ⇒ 竞态**。前几轮按「某个用例有 bug」修全部白费；
  必须按「销毁时机不可控」这类**系统性成因**处理。
- **涉及远端状态的结论必须先 `git fetch` 再下**。
  「v9.1.3~v9.3.2 tag 断档」就是未 fetch 导致的**误判**，已更正（远端一直有）。

## 4. 可复用的诊断命令（下次复现同类崩溃直接用）

```bash
# ① 判断一个 Qt 对象是「引用计数回收」还是「循环 GC 回收」
./.venv/Scripts/python.exe -c "
import gc,sys,tempfile,weakref; sys.path.insert(0,'.')
import os; os.environ.setdefault('QT_QPA_PLATFORM','offscreen')
from PyQt6.QtWidgets import QApplication
app=QApplication.instance() or QApplication(sys.argv)
from pathlib import Path
from gcm.db.repo_db import Database; from gcm.db.settings import SettingsStore
from gcm.ui.main_window import MainWindow
d=tempfile.mkdtemp(); w=MainWindow(data_dir=d, db=Database(Path(d)/'t.db'), settings=SettingsStore(Path(d)/'s.json'))
gc.collect(); r=weakref.ref(w); del w
print('del 后立即回收:', r() is None)      # False ⇒ 有环，靠 GC
print('gc.collect 回收数:', gc.collect())  # >0   ⇒ 确认循环垃圾
"
# ② 拿到原生崩溃的 C 栈（SIGSEGV 下 atexit 不执行，只有它能留痕）

# ③ 改变分配时序以二分定位（会让崩溃消失，属诊断手段不是修复）
PYTHONMALLOC=debug QT_QPA_PLATFORM=offscreen ./.venv/Scripts/python.exe -m coverage run --source=gcm scripts/ci_run_fast.py
# ④ 模拟非 UTF-8 控制台（复现 Windows runner 的编码问题）
PYTHONIOENCODING=cp1252 ./.venv/Scripts/python.exe -m gcm.mcp_server   # 等
```

## 9. 压测记录（2026-10-17 · v9.4.3）

### 9.1 并发幂等压测 —— **抓到真 bug**

| 项 | 内容 |
|---|---|
| 方法 | 40 线程 + `threading.Barrier` 同时起跑，同 payload 调 `maybe_notify`，网络 mock |
| 期望 | 真正发送 1 次 |
| **实测（修复前）** | **13 次**（审计：sent=13 / dedup-skip=27） |
| 根因 | 去重是「先查后写」：锁只保护查询，**发送期间没占位** → 40 个线程几乎同时通过查重 → check-then-act 竞态 |
| 修法 | 锁内一次性「查重 + 占位」（发送前写 `_recent[fp]`）；失败再撤销自己那次占位 |
| 实测（修复后） | **发送 1 次**，dedup-skip 39，审计 40 行全部合法 JSON |
| 回归 | `tests/test_g69_notify_hardening.py::TestConcurrentIdempotency`(2) |

> **教训**：`maybe_notify` 的兜底 `except` 会把**测试自身**的 `NameError` 也吞掉
> （写回归时漏了 `import time`，表现为「发送成功但审计记 failed」）。
> 兜底 `except` 是必要的，但意味着**测试必须能自己独立复现**，不能只依赖被测函数的返回值。

## 11. 独立审查整改（v9.4.5）

对 v9.4.2–v9.4.4 跑了**独立对抗式审查**，结论 **Request Changes**（5 个阻塞项）。

### 11.1 ★ 我上一轮说「引用环已根治」是**假绿**

`_layout_timer.timeout.connect(lambda: self._apply_layout_for_width(self.width()))`
—— 不 `show()` 时窗口确实能按引用计数释放，**但 `show()` 后 `resizeEvent` 会创建这个定时器，
lambda 立刻把环重新接上**。而我的守卫 `TestG69_18NoMainWindowRefCycle` **从不调用 `show()`**，
所以永远绿。

| 状态 | 实测 |
|------|------|
| 修复前（show 后） | `del w` 后未释放，需 `gc.collect()` |
| 修复后（改绑定方法） | `show()` 后 `del w` **立即释放** |

**并存的结论**：正因为补上了这最后一环，才敢**移除 runner 的 `gc.disable()` 安全网** ——
恢复正常 GC 后全量**连跑 3 次绿**（1115 用例、0 崩溃）。

> 教训：守卫必须覆盖**生产路径**（`show()`），不能只覆盖「方便测试的路径」。
> 这条和项目里「测试直接构造后端对象绕过 UI 断链」是同一类错误。

## 13. G58-2 镜像多备援（v9.5.0 · 2026-10-18）

### 13.1 为什么不用 HTTP HEAD 判断镜像

实测（2026-10-18，本机）：

| 镜像 | HEAD | `git ls-remote` | 结论 |
|------|------|-----------------|------|
| `gh.llkk.cc` | 403 | ✅ | HEAD 不可信 |
| `gh-proxy.com` | 200 | ✅ | 可用 |
| `ghfast.top` | 403 | ✅ | HEAD 不可信 |
| `ghproxy.net` | 403 | ✅ | HEAD 不可信 |
| `ghproxy.com` | 200 | ❌（302 重定向） | HEAD 假阳性 |
| `mirror.ghproxy.com` | TLS EOF | ❌ | 不可用 |
| `ghps.cc` | 403 | ❌ | 不可用 |

因此探测命令固定为 `git -c credential.helper= ls-remote --exit-code <url> HEAD`
（不弹凭据框、不读钥匙串；退出码 2 视为空仓库可达）。

### 13.2 内置镜像（按实测中位延迟排序）

`gh.llkk.cc`（~2.4s）→ `gh-proxy.com`（~3.3s）→ `ghfast.top`（~3.6s）→ `ghproxy.net`（~8.0s）

### 13.3 真实端到端（本机实测）

```
   → status=SUCCESS · 6.7s · 日志：镜像不可用 → 国内镜像均不可用，回退源站
```
