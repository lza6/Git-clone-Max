### 2.2 引用环守卫（历史 SIGSEGV 根因）

```
QT_QPA_PLATFORM=offscreen ./.venv/Scripts/python.exe -m unittest \
  tests.test_g69_regressions.TestG69_18NoMainWindowRefCycle \
  tests.test_g69_regressions.TestG69_18NoCycleAfterShow
```

结果：**OK**。

> **第一次跑是红的**：`UndoBar` 持有 `self._owner = owner` 强引用，而主窗持有 `undo_bar`，
> 构成引用环（窗口只能等循环 GC 回收；循环 GC 在任意分配点触发，Qt 曾在事件分发中途
> 销毁控件导致 SIGSEGV）。改成 `weakref.ref(owner)` 后转绿。
> 这条不是"顺手修"，是本项目历史最贵的一个 bug 的同型问题。

第一次跑快集时 **3 个模块红**，都是真问题，逐一修完才转绿：

| 红项 | 真因 | 修法 |
|------|------|------|
| `test_ui_compact_visibility`（1020×560） | 菜单栏占一行，把主操作区挤掉了（`btn_open` 只剩 17/42 像素） | **抬高最小高度 24px**，而不是压小按钮 —— 压小会直接违反「主操作区必须完整可见」 |
| `test_i18n_coverage` | `'已清空输入区'` 漏了 zh/en | 补两条文案 |
| `test_function_size_budget` | 我把浮条样式内联进 `_build_qss`，它变成全库最长函数（261 行 > `MainWindow.__init__` 255 行） | 把浮条样式抽成 `_undo_bar_rules()`，`_build_qss` 降回 245 行，最长函数回到已登记的 `__init__` |

> **一次失误的记录**：为了判断 1020×560 裁切是不是我引入的，我执行了 `git stash`。
> 该操作把工作区换成已暂存版本，与未跟踪文件冲突，留下了 5 个文件的冲突标记。
> 已全部手工合并（一律取本轮值）并清理干净，随后 `ruff` / `mypy` / 28 用例 / 全快集复验通过。
> 教训：**判断基线不要动工作区**，用 `git worktree add <tmp> <commit>` 隔离对照。
