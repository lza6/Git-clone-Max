## 2. 关键改动

### 2.1 设计系统 / 对比度

- `gcm/ui/theme.py`：新增 `on_accent`、`border_strong`、`success` 语义色；修正
  `_luminance` 的绿/蓝权重写反（历史对比度计算全部失真）；QSS 缓存；字号全链路派生；
  `QTabs::pane` → `QTabWidget::pane`；危险按钮改描边样式。
- 实测对比度：deep 主按钮白字 2.53:1 → 深字 7.49:1；Nord 弱文本 2.82 → 4.80；
  Nord 错误色 3.05 → 4.65；各主题输入边界 ≥3.51:1。
- `gcm/ui/qss_validate.py`：新增控件类名白名单（能拦住 `QTabs` 这类拼写错误）。

### 2.2 响应式

- 新增 `gcm/ui/layout.py`：`layout_mode` / `effective_minimum` / `clamp_window_size` /
  `fit_dialog_to_screen`。
- 主窗下限从 1020×700 改为按屏幕工作区推导（1366×768@125% 逻辑视口约 1093×614 可放下）；
  输入/选项/按钮区域放入可滚动容器（`download_top_scroll`，最小高 160），
  与进度表之间用纵向 `QSplitter` 分配高度；8 个对话框按屏幕 90%×85% 夹取。
  实测 1020×560 下输入框可见高度 120/120（修复前 46/120）。
- Compact 模式隐藏快捷填充按钮与设置导航；`Ctrl+1/2/3` 切页签并记忆最后页签。

### 2.3 性能

- 进度列从「每行一个 QProgressBar」改为 `ProgressDelegate` 自绘；
  进度值放内存字典，250ms 单次合批，仅重绘视口。
- 批量插行期间关闭排序；完成动效限 8 并发、600ms；QSS 结果缓存。
- 管理页 500 仓延迟到首次激活加载。
- 本地 HTTP API：读端点使用只读连接、分页下推 SQL。

### 2.4 无障碍与空态

- 输入框/主按钮/取消/进度表/管理表/设置搜索/日志/图表补 `accessibleName` 或
  `accessibleDescription`；表格与页签补焦点环。
- 进度过滤到 0 行、设置搜索无结果均显示明确空态。

### 2.5 缺陷修复

1. 进度过滤只按**首段**文本过滤（定时器 lambda 捕获旧 `text`，且形成引用环）。
2. 过滤到 0 行时不显示空态。
3. 统计对话框存储/评分文本使用字面量 `\n`（界面显示 `\n` 而非换行）。
4. 对话框套导入时生成的静态深色 QSS，切换 Light/Nord/HC 后失效。
5. 高亮器/统计图/进度闪烁色固定读深色板。
6. 统计对话框、导入向导、仓库详情删除静态 QSS 依赖。
7. 默认深色主题主按钮对比度不足（见 2.1）。

### 5.2 产物健康检查（诚实边界）

```bash
./.venv/Scripts/python.exe scripts/health_check.py --json dist/health_check.json
# [OK] version_match: src='9.7.0' artifact='9.7.0'
# [OK] artifacts_exist: true
# [OK] started_ok: process alive after 30s
# [FAIL] repos_db_created: 缺失
```

**结论与对照**：本会话无法完成「打包 GUI 真正初始化」的冒烟。为避免误判，
另外做了三组对照：

| 对照 | 结果 |
|------|------|
| 源码 GUI（`python -m gcm` + `GCM_DATA_DIR`） | **PASS**：创建 `.instance.lock` / `repos.db` / `clones` / `lists` |
| 打包 exe `--cli --json` | **PASS**：输出 `version: 9.7.0`，退出码 2（空输入，符合契约） |
| 从 Release 下载的 v9.6.1 exe | **同现象**：同环境同样停在 bootloader、不创建数据目录 |

因此 `repos_db_created=false` 判定为**本会话环境限制**（冻结 bootloader 在非交互
桌面会话中未完成初始化），不是 v9.7.0 的回归。发布前需在真实桌面环境人工双击
复验一次 GUI；这是本轮唯一未闭环的验证项。

### 5.3 部署语义说明

本产品是**桌面单机应用**，没有服务端 / staging / 生产集群：
「部署」= 发布 GitHub Release（双产物），客户端通过现有更新检查发现新版本。
因此不存在服务端热更新、数据库在线迁移或流量灰度；回滚方式是重新安装上一版
`v9.6.1`（数据模型只新增了一个带默认值的 `last_tab` 字段，向后兼容）。
