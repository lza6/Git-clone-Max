## §5b 发布前增量（弱引用崩溃修复）

快集第 2 轮发现 `tests.test_rev14_feedback + tests.test_g71_event_stream`
组合偶发原生崩溃（10 轮 6 崩，崩点均在 GuiHostsLocalApi 末尾）。
**A/B 归因**：基线 worktree（6e68cc4，改动前）同序列 6/6 绿 + 最小三段链
（OfflineIndicator → EventPanel → MainWindow 构建）3/3 复现 → **本轮引入**。
根因：C1 的 `QTimer.singleShot(FAST_MS, lambda: btn.setText(...))` 强捕获按钮；
测试销毁 panel 后 Timer 事件派发触碰已释放的 C++ 对象。
修复：回调改 `weakref.ref`（`_restore_text`，按钮存活才恢复文案）——与项目
「信号连接不捕获强引用」既有纪律同源（`6c79370`）。
修复后：同序列 8/8 绿 + verbose 3/3 绿 + 六模块 178 例绿 + ruff/mypy 绿。

**第二波（CI 反馈）**：首版弱引用修复仍带 try/except（except 预算 798>797、
pass-only 287>286，CI g80_hygiene 红，run 44551909152）。终版三步归位（`60436fa`）：
① 4 个 C1 测试重写为**不泵事件循环**（回弹断言直调 `_restore_text`，
新增「按钮销毁后恢复回调静默跳过」用例）——跨用例延迟析构的触发面被移除；
② `closeEvent`/`snapshot` 的 `except Exception` 窄化为 `RuntimeError` + applog 留痕；
③ 两处 applog 中文日志走 `tr()`，zh/en 字典补 2 键（i18n 基线回落）。
终验：rev14+g71 **77 例绿** × 3 连跑稳定、verbose 3/3、六模块 **179 例绿**、
ruff 0 error / mypy 157 files / DRIFT 0 / I18N OK。
