## 2. Rev6 前提复核：6 条被推翻或显著收窄（**本节最重要**）

> 复核方法：把 Rev6 的每条技术前提，用本轮真实运行/真实读码重新验一遍。
> **不重复 Rev6 已经正确的内容**，只列变了的部分。执行方若照 Rev6 原文排期，会做错四件事。

### 2.1 ❌ 推翻：Rev6「B4-1 用 FTS5 `trigram` 解决中文检索」—— 中文两字词会**全部搜不到**

Rev6 §B4-1 写：「分词器必须用 `trigram`，不要用 `unicode61`——后者对中文按字切分……`trigram` 才能做中文子串匹配。」

**本轮实测（SQLite 3.50.4）**：

```
trigram MATCH '克隆'   -> []          ← 两字中文词：**零命中**
trigram MATCH '机器'   -> []          ← 零命中
trigram MATCH '学习'   -> []          ← 零命中
trigram MATCH '机器学' -> [(2,)]      ← 三字：命中
trigram MATCH 'lza6'   -> [(1,)]      ← 英文/数字 4 字符：命中
LIKE  兜底 '克隆'      -> [(1,'lza6')] ← LIKE 能命中
```

`已验证`。原因：`trigram` 按**三字符**切片，查询串不足 3 个字符时 FTS5 规定「match nothing」。

**后果**：中文用户最常搜的是**两个字**（「克隆」「爬虫」「量化」「笔记」）。若照 Rev6 建 `trigram` 索引，上线当天就会被报「搜索坏了」。

**修正后的方案（写进 §5 的 C4 批）**：三段式
1. `len(q.strip()) >= 3` → 走 `trigram` FTS（`bm25` 排序 + `snippet` 高亮）；
2. `len(q.strip()) < 3` → 走**现有的 `SearchMixin.search_repos`（LIKE 下推）**，本轮实测 3000 行只要 3.5 ms，两字查询完全够用；
3. 两条路径**共用同一个返回 schema**，由 `db/repo_search.py` 做单一入口分发 —— 调用方（管理页 / `GET /api/repos/search` / MCP）不需要知道走了哪条。

> 这条同时说明另一件事：**FTS5 在 3000 仓库这个量级不是必需项**。它解决的是「排序相关性 + 高亮 + 万级」，
> 不是「现在搜不动」。所以它的优先级应该**低于** §3 的三处真缺陷。

### 2.2 ❌ 收窄：Rev6「B3-2 管理页必须窗口化/分页，否则 3000 仓库首屏 <300ms 做不到」

**本轮实测**：`list_repos()` 取全量 3000 行 **14.7 ms** → `ManageModel.set_rows()` **4.3 ms** → 表格绑定+渲染 **4.0 ms**。
**总计约 23 ms，远优于 Rev6 定的「<300ms」目标，且这是包含全部列的全量渲染。**

`已验证`。所以：
- **分页不是当前瓶颈**，Rev6 把它排在 P0 是**基于估算而非测量**；
- 真正的规模瓶颈是**别处**：`dir_size` 15 万文件 **484 ms**（而且它是**递归 stat**，机械盘/杀软下会慢一个量级）、`prune_history` 10 万行 **164 ms**（且在 GUI 线程）；
- 因此 §5 的 C3 批把「分页」降为 **P2（等真的有万级用户再说）**，把「`dir_size` 异步化 + 缓存」提为 **P1**。

### 2.3 ❌ 收窄：Rev6「B3-4 数据库增长治理」—— 前提还在，但量级没那么急

Rev6 说 `prune_history` 会「每 100 个结果帧卡一次（全表窗口函数）」。本轮实测：**10 万行 164 ms / 2 万行 35 ms**。
`已验证`。判读：**会有一帧 164ms 的卡顿，但不至于「卡死」**；优先级 P2 而非 P1。真正该动的是把它挪出 GUI 线程（与 §1.5 的 `dir_size` 同一类改法）。

### 2.4 ❌ 推翻：Rev6 隐含「A5-5 的 per-host 并发闸门已经是可配置能力」

`CLAUDE.md` §6 与 v9.11.0 changelog 都写「per-host 并发闸门，`host_concurrency` 可注入」。
**本轮实测：注入不生效。**

```python
>>> from gcm.app.engine import SyncEngine
>>> e = SyncEngine(tmp, host_concurrency=9)
>>> e._host_concurrency
4          # ← 传 9，实际 4
>>> e2 = SyncEngine(tmp, host_concurrency=0)   # 0 的语义是「不限流」
>>> e2._host_concurrency
4          # ← 传 0，实际也是 4；「关闭闸门」这个能力不存在
```

`已验证`。根因（`静态确认`）：`gcm/app/engine.py:121` 按参数赋值，**`:192` 又无条件 `self._host_concurrency = 4` 覆盖了一次**。
加上 `set_host_concurrency()` **全库只有 tests 调用**（`grep` 零生产调用点）→ 结论：**这是「可配置性伪装」：参数存在、值恒为硬编码 4、用户无法改、也无法关。**
这正是 `CLAUDE.md` §5 那条红线的原话：「新增的模块/函数/设置项必须有生产调用点或 UI 入口（只在 tests 里出现 = 虚伪实现）」。
详见 §3.2（缺陷 X-1）。

### 2.5 ❌ 建议不采纳：Rev6「B8-5 ActionRegistry 一份定义喂四处」

按 Rev6 的写法（注册表 → 菜单/工具栏/托盘/命令面板/CLI/MCP 全从同一份生成），**会正面撞上项目的三条边界冻结**（`test_g80_boundaries`）与「不许重构」的用户要求：

### 3.1 X-4【P1】1366×768 笔记本上，「保存清单 / 载入 / 导入 Star」三个按钮只露出 10px

**这是本轮唯一一个「在真机上第一眼就能看到」的缺陷。**

复现（`已验证`，offscreen 几何断言 + 截图）：

```
窗口 1240×729（= clamp_window_size(1240,840, 1366,768)，即 1366×768 笔记本上的实际窗口）
顶部滚动区 viewport 高 = 284，内容高 = 316 → 溢出 32px，vbar_max=32
btn_save_list    可见区 86×10 / 实际 86×42
combo_load_list  可见区 448×6 / 实际 448×34
btn_load_list    可见区 60×10 / 实际 60×42
btn_star_import  可见区 125×10 / 实际 125×42
```

同一窗口在 **1440×900** 下四项全部完整可见；在 **1216×684**（= 1920×1080@150% 的实际窗口）下四项**完全不可见（0×0）**。

截图佐证：`download_deep_1366x768.png` 里该行只剩 4 个**空白的圆角框**（按钮只露出顶部边缘）—— 用户看到的是「一排没有字的空框」。

`静态确认` 根因：这四个控件属于顶部**可滚动区**（`main_window.py:834 download_top_scroll`）的**最后一行**；
窗口变矮时滚动区把最后一行切掉，而**滚动条默认在最顶**，用户不会想到「要往上滚才能看到保存清单」。

**为什么它比 Rev6 的 U 系列都重要**：1366×768 是笔记本最常见分辨率，`layout.py:4` 的注释自己写着「最低目标是让 1366×768@125% 可用」。
**现在这个目标是没达成的**，只是之前没人用几何断言量过（截图审计脚本只存图、不断言）。

**最小改法（三选一，按推荐序）**：
1. **把这四个控件移出滚动区**，钉在滚动区下方、与「开始并行下载/更新」同一常驻行（推荐：一劳永逸，且符合「主操作区常驻」的既有设计原则）；
2. 顶部区域的**最后一行加 `setMinimumHeight` 并把滚动区 `ensureWidgetVisible`**——启动时滚到底（体验差，用户看不到地址框顶部）；
3. 紧凑档（`layout_mode=compact`）把这四个控件收进一个「清单 ▾」菜单按钮（新增下拉，回归面小但要测菜单）。

**验收（必须能失败）**：新增 `tests/test_ui_compact_visibility.py`，在 `1240×729` 与 `1216×684` 两个尺寸下断言
`widget.visibleRegion().boundingRect().size() == widget.rect().size()` 对**主操作区所有按钮**成立；
在改之前跑应**红**（本轮实测确认这 4 个会红）。

### 3.5 X-5【P2】英文模式下有 58 处文案会**回退成中文**

`已验证`（AST 统计）：


这样「新文案必须同时进两本字典」这条 `CLAUDE.md` §3 的约定才真正被强制，而不是靠记性。

另：`gcm/ui/` 下还有 **1103 处**非 docstring 中文字面量（`main_window` 180 / `settings_groups` 165 / `repo_detail_dialog` 94…）。
**不必全清**（大量是日志与内部字符串，不需要翻译），但守卫应能给出「还剩多少」的稳定数字，只许降不许升（与 `test_g80_hygiene` 的预算制同款）。

### 9.1 度量采集脚本（复核本文件是否过期，直接复制运行）

```python
#!/usr/bin/env python
"""scripts/dev_metrics.py —— 一次性打印本指南 §1.3/§1.4 的全部数字。
用途：让「文档写了就信」变成「跑一遍就知道文档过没过期」。建议纳入 C1-13。"""
import ast, pathlib, re, subprocess, sys

ROOT = pathlib.Path(__file__).resolve().parent.parent


def py_files(sub: str) -> list[pathlib.Path]:
    return sorted(p for p in (ROOT / sub).rglob("*.py") if "__pycache__" not in p.parts)


def main() -> int:
    gcm = py_files("gcm")
    sizes = {p.relative_to(ROOT).as_posix(): len(p.read_text(encoding="utf-8").splitlines()) for p in gcm}
    over800 = sorted(p for p, n in sizes.items() if n > 800)
    over500 = sorted(((n, p) for p, n in sizes.items() if 500 < n <= 800), reverse=True)
    print(f"gcm .py 文件数 = {len(gcm)}  总行数 = {sum(sizes.values())}")
    print(f">800 行（{len(over800)}）：{over800}")
    print(f"500-800 行：{[f'{n} {p}' for n, p in over500]}")

    # 超 100 行函数
    big = []
    for p in gcm:
        lines = p.read_text(encoding="utf-8").splitlines()
        cur, start = None, 0
        for i, line in enumerate(lines, 1):
            m = re.match(r"^(\s*)(?:async\s+)?def\s+(\w+)", line)
            if m and len(m.group(1)) <= 4:
                if cur and i - start > 100:
                    big.append((i - start, p.relative_to(ROOT).as_posix(), cur))
                cur, start = m.group(2), i
        if cur and len(lines) + 1 - start > 100:
            big.append((len(lines) + 1 - start, p.relative_to(ROOT).as_posix(), cur))
    big.sort(reverse=True)
    print(f"\n>100 行函数 = {len(big)}（最大三个：{big[:3]}）")

    # except 预算
    total = only_pass = 0
    for p in gcm:
        try:
            tree = ast.parse(p.read_text(encoding="utf-8"))
        except SyntaxError:
            continue
        for node in ast.walk(tree):
            if isinstance(node, ast.ExceptHandler):
                total += 1
                if len(node.body) == 1 and isinstance(node.body[0], ast.Pass):
                    only_pass += 1
    print(f"except 子句 = {total} / pass-only = {only_pass}")

    tests = sorted((ROOT / "tests").glob("test_*.py"))
    print(f"tests/ test_*.py = {len(tests)}  总行数 = "
          f"{sum(len(p.read_text(encoding='utf-8', errors='replace').splitlines()) for p in tests)}")

    # 版本单源
    version = re.search(r'__version__\s*=\s*"([^"]+)"',
                        (ROOT / "gcm/__init__.py").read_text(encoding="utf-8")).group(1)
    print(f"__version__ = {version}")
    print("（覆盖率与快集用例数需另行运行，见 §1.2 的两条命令）")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```
