## 1. Executive Summary

本计划面向 Git-clone-Max 现有 PyQt6 桌面客户端（9.19.0），不是新建 Web 前端。核心判断是：响应式骨架、四主题与基础无障碍已经成立，当前要修的是设置页工作区、900px 导航、无障碍审计噪声与度量口径；性能上实际启动中位数约 1.99–2.51s，已低于 3.5s 目标，因此不重写、不为已达标路径写优化代码。三个里程碑共 14 个任务，先修真实摩擦，再做设计系统、触摸与自动主题，最后用视觉回归和发布门禁收口。

## 1.1 适用范围：这里没有 Web 应用

模板要求的是“现有 Web 应用的响应式、性能、设计系统与 UX 升级”。按本项目代码事实，这个前提不成立：

| 事实 | 证据 |
|---|---|
| GUI 是 PyQt6 桌面程序 | `gcm/__main__.py` 启动 `QApplication`；`gcm/ui/` 是 Qt Widgets |
| 没有 HTML 前端 | `gcm/http_api.py` 只输出 JSON / SSE / CSV；无 `gcm/web/`、无静态页面 |
| 没有位图资源 | 图标走 `QStyle.standardIcon`；打包资源里没有需要 `srcset` 的图片 |
| 目标用户不是手机用户 | 产品定位见 `docs/product-brief.md`：个人开发者、半技术用户、Windows 优先 |

所以本文把模板逐项**同构替换**为桌面等价物，不硬造不存在的移动端分支：

| Web 模板项 | 本项目对应物 |
|---|---|
| 320 / 768 / 1024 / 1440px 断点 | 逻辑像素档位 XS / S / M / L：900（支持下限）/ 1020 / 1100 / 1440 |
| mobile-first / desktop-first | **desktop-first + 密度自适应** |
| LCP / INP / CLS | 冷启动到可交互 / UI 线程单次操作 / 首帧后布局位移 |
| srcset / art direction | 多 DPI 图标策略；本项目零位图 |
| dvh / svh / lvh、刘海安全区 | 多显示器工作区、任务栏、DPI 缩放、Windows 贴靠 |
| Service Worker / 离线缓存 | 失败分类 + 持久重试队列 + 离线指示；不引入浏览器缓存 |
| CSS containment / GPU 合成 | 避免整窗 `setStyleSheet`、限制 delegate 重绘范围 |
| 底部导航 / 汉堡菜单 | 三页签 + 设置分组导航 + `Ctrl+K` 命令面板 |

> **如果真实目标是新建一个 Web 控制台**，那是另一个产品决策：需要新增前端工程、鉴权、部署与安全边界，不能混进本计划。本文按“增强现有桌面应用”交付。

## 1.3 现状与取舍

Git-clone-Max 的 UI 已经过了“补断点、补主题、补基础无障碍”的阶段：当前有 4 套主题 × 6 个强调色、7 级排版角色、XS/S/M/L 四档断点、多显示器重算、骨架屏、空态、离线指示、键盘 Tab 链与 64 个适配回归用例。真正影响日常使用的不是“再加一个断点”，而是三个具体工作区问题：设置页的日志区与设置区各占一半，导致 1024×768 下设置内容只剩很窄的一条；900px 受支持宽度下设置分组导航直接消失；无障碍审计被 Qt 内部子控件污染，真正的管理页搜索框反而漏名。性能方面，**把“健康检查总耗时”误当成“启动耗时”是当前最大的度量错误**：`health_check.elapsed_ms` 包含 42.8MB exe + 82.2MB zip 的 SHA-256 与版本检查；实际启动冒烟中位数约 1.99s（onefile）/ 2.51s（portable），已低于 3.5s 目标。因此本计划**不重写、不引入 Web/Electron、不优化已达标的热路径**；先修工作区与度量真实性，再做设计 token、触摸密度、自动主题与视觉回归，最后用成对矩阵和发布门禁收口。三个里程碑、14 个任务，每个任务都有文件落点与可断言验收。

## 2. Responsive Strategy

### 2.1 当前断点与真实可达范围

`gcm/ui/layout.py` 已经定义并消费四档：

| 档位 | 判定 | 真实锚点 | 当前行为 |
|---|---|---|---|
| **XS** | `w < 1020` 或 `h < 580` | 900×480、911×512（`effective_minimum()` 夹取后的真机小屏） | 工具行折叠进「更多 ▸」；进度表/管理页隐次要列；设置导航折叠 |
| **S** | `1020 ≤ w < 1100` 或 `580 ≤ h < 820` | 1024×768、1240×729、1366×768 | 隐快捷填充与设置导航；结论条单行；行高 24 |
| **M** | `1100 ≤ w < 1440` 且 `820 ≤ h < 1000` | 1280×800、1440×900（部分） | 全量控件；行高 26 |
| **L** | `w ≥ 1440` 且 `h ≥ 1000` | 1600×1000、1920×1080 | 管理页列宽加宽；进度表行高 28；宽屏留白重新分配 |

关键常量：

- `WINDOW_DEFAULT = (1240, 840)`，`WINDOW_MIN = (1020, 560)`，`ABSOLUTE_MIN = (900, 480)`。
- `effective_minimum(avail_w, avail_h)` 会按屏幕工作区把最小窗口夹到 90%/85%，所以**只抬高 `WINDOW_MIN` 不能解决小屏裁切**；必须同时使用 `tools_fold_height(scale)` 的折叠判定。
- 断点按**逻辑像素**定义，Qt 已处理 DPI 缩放；不要按 `devicePixelRatio` 再乘一遍。

### 2.2 desktop-first 还是 mobile-first

**采用 desktop-first + 密度自适应，不做 mobile-first。**

理由不是偏好，而是用户数据与代码事实：

- 产品只有桌面 GUI；没有移动端入口，也没有 Web 页面。
- 主要场景是 1366×768@125%/150% 笔记本、1920×1080 办公屏、分屏窄窗与高 DPI 缩放。
- 320/768 的移动断点在本项目里**不可达**，硬加只会变成第二个 `w < 768` 死分支——历史上 `_apply_layout_for_width` 就因此被 `AttributeError` 静默吞掉，任何列都没折叠。

“移动”在本文中只指：**小屏笔记本、分屏窄窗、触摸屏笔记本、远程桌面**。

### 2.3 布局修订

#### A. 设置页：日志区改为可调分割，不再 1:1 抢高度

当前 `main_window._build_settings_tab()` 把 `settings_scroll` 与 `log` 组都按 `stretch=1` 加进同一个 `QVBoxLayout`，两半各占 50%。1440×900 下设置内容只剩约 250px 高；1024×768 下更窄，用户每改一个设置都要在极小视口里滚动。

目标结构：

```
设置页
├─ 顶部工具行：设置导航（宽屏列表 / 窄屏下拉） + 搜索
└─ QSplitter(Qt.Vertical)
   ├─ settings_scroll        ← 默认 72%，最小 240px
   └─ log_group              ← 默认 28%，最小 120px，可折叠
```

具体值：

- 默认比例 **72 / 28**；`setStretchFactor(0, 3)`、`setStretchFactor(1, 1)`。
- 1440×900 初始 `setSizes([520, 200])`；1024×768 初始 `setSizes([430, 170])`。
- `setCollapsible(1, True)`；日志组标题右侧加「收起日志 / 展开日志」`QToolButton`，状态持久化到 `settings.ui_state["settings_log_collapsed"]`。
- 分割比例持久化到 `settings.ui_state["settings_split"]`；恢复时夹到 `[240, 120]` 与当前高度的 85%，坏值回退默认，不抛异常。
- 不要给 `log_view` 再设固定高度；保留 `minimumHeight(80)` 作为底线。

验收：

- 1024×768 离屏真实主窗：`settings_scroll.height() >= 300`，`log_view.height() >= 80`（实测 91；日志组总高约 179）。
- 1440×900：`settings_scroll.height() >= 420`，日志仍可读。
- 拖动分割条后重启，比例保持；损坏的 `ui_state` 不崩。
- 下载页/管理页的 `QSplitter` 初始尺寸不受影响。

#### B. 900px 宽度：设置分组导航改为紧凑下拉

当前 `_apply_layout_mode()` 只有一句 `nav.setVisible(self.width() >= 1000)`。1024 宽可见，900 宽直接消失；而 900×480 是 `ABSOLUTE_MIN` 明确支持的尺寸。

目标：

- `width >= 1000`：保留左侧 `settings_nav` 列表（150–220px）。
- `width < 1000`：隐藏列表，显示 `settings_nav_combo`（`QComboBox`），内容为同样的 `01 启动与后台运行 … 07 数据洞察` 短标题；选中即滚动到对应分组。
- 两者共享同一个 `goto_section()` 映射；不要复制一份标题表。
- `settings_nav_combo` 加入设置页 Tab 链，位于 `settings_search` 之前。

验收：

- 900×480：combo 可见、列表隐藏；选「06 本地 API / 事件流」能滚到对应组。
- 1024×768：列表可见、combo 隐藏；`Ctrl+3` 进入设置页后焦点顺序正确。
- `grep` 不再出现“只隐藏、无替代入口”的分支。

#### C. 管理页：窄屏列优先级

管理页当前 8 列：仓库、作者/仓库、本地路径、上次同步、HEAD、历史、健康、大小。1024 宽下仓库名和路径都被压缩，健康/大小仍占固定宽。

建议在 **XS/S（<1100）隐藏「健康」「大小」**两列，把宽度让给仓库名与路径；在 M/L 恢复。理由：

- 健康分与大小是“辅助判断”，仓库名/路径/上次同步是“找到目标”的必需信息。
- 详情对话框仍可查看完整信息；隐藏不等于丢失。
- 与进度表已有的“窄窗隐大小/健康”策略一致，不新增第二套响应式逻辑。

验收：

- 900/1024 宽无横向滚动；仓库名列宽比当前增加 ≥80px（实测截图对比）。
- 1440/1920 宽 8 列全显示。
- 列宽持久化仍按“可见列”保存；重新变宽后恢复。

#### D. 下载页：保持现有折叠策略，不重做

当前下载页已经做到：

- 顶部区可滚动，动作区常驻；
- 高度 < `tools_fold_height(scale)` 时工具行折叠进「更多 ▸」；
- 进度表在矮窗让位；
- 1020×560 / 900×480 有守卫。

本计划**不改这块**。只补一个测试：900×480 @ 1.6 字号下，`btn_start`、`btn_cancel`、`btn_more_tools` 的 `visibleRegion == rect`；如果失败，按现有折叠原则修，不另造布局。

### 2.4 触控、指针、键盘

| 项 | 现状 | 目标 | 落点 |
|---|---|---|---|
| 触控目标 | 表格行 34px（触摸屏），主按钮 38–42px | 主操作 ≥44px；行 ≥34px；控件间距 ≥8px | `TOKENS["control"]["touch"] = 44`；`_apply_wide_layout()` 在 `has_touchscreen()` 时设置主按钮最小高度 |
| hover | 表格行 hover 已有；按钮 hover 已有 | 保持；不要把 hover 作为唯一状态编码 | `qss_build.py` 现有规则 |
| 键盘 Tab | 三个页签有显式链；设置内容依赖 Qt 默认 | 设置页 combo/搜索/滚动区进链；对话框 Esc 默认关闭 | `focus_order.py` + `settings_workspace.py` |
| 焦点可见 | `:focus` 覆盖 9 类控件 | 新增控件必须有焦点环 | `qss_build.py` 守卫 |
| 快捷入口 | `Ctrl+K`、`Ctrl+1..3`、`F6` | 保持；设置页 combo 可用键盘选择 | `menu_bar.py` 帮助页同步 |

**不引入双指手势、pinch、长按菜单**：桌面鼠标/触控板已由原生滚动与右键菜单承担；自绘手势会与滚动条打架，收益低于回归成本。

### 2.5 多显示器、工作区、安全区等价物

现有实现已经覆盖大部分：

- `QGuiApplication.primaryScreenChanged / screenAdded / screenRemoved` → `_on_screen_changed` 重算最小尺寸并夹取窗口。
- `_serialize_geometry` 存 `@屏名`；拔屏后找不到屏名 → 回主屏 + WARN。
- `availableGeometry()` 排除任务栏；Windows Snap 的 ±4px 由 0.95/0.85 夹取覆盖。

本计划只补两件事：

1. `QScreen.logicalDotsPerInchChanged` / `geometryChanged` 变化时重跑一次布局（远程桌面缩放、改分辨率）；用绑定方法连接，避免引用环。
2. 把“屏幕变更测试”从纯函数扩展到离屏注入：假屏幕列表 → `minimum_for_screen()` / `resolve_screen()`；真实拔插仍标 `待验证`，不伪造通过。

**dvh/svh/lvh、刘海安全区：不适用**。Qt 没有视口单位；桌面没有刘海。强行模拟只会引入不可测代码。

### 2.6 字号缩放与图片/图标

- `font_scale` UI 下限 0.9、上限 1.6；DPI ≥150% 时 `clamp_scale_for_dpi()` 自动抬到 ≥1.0。
- 字号改变必须重跑 `_apply_layout_mode()`；现有 `test_font_scale_change_reevaluates_fold` 已守住。
- 本品零位图：`QStyle.standardIcon` 16 个语义映射；需要品牌图标时用单色 `QPainter` 路径，颜色取 `current_palette()["text_dim"]`，随主题走。
- 多 DPI 由 Qt `QIcon` 内建多尺寸承担；**不打包 ttf/ico/svg 资源集**。

### 2.7 常见陷阱

| 陷阱 | 为什么会发生 | 避免方式 |
|---|---|---|
| 加 320/768 断点 | 模板惯性；但 `ABSOLUTE_MIN=900` 使这些分支不可达 | 断点必须能被真实拖动到达；测试矩阵从 900×480 起 |
| 只改 `WINDOW_MIN` 抬最小高 | `effective_minimum()` 会按屏幕夹回 | 高度不够时折叠工具行，且让可滚动区先让位 |
| 用宽度判断一切 | 高度也会导致裁切；字号变化会改变需求高度 | 宽度定档位，`tools_fold_height(scale)` 定折叠 |
| 把 `wide` 做成死枚举 | 只返回不消费，等于没有 L 档 | 每个断点必须有可测量行为差异（行高/列宽/留白） |
| 固定高度/固定宽度 | 高 DPI 与 1.6 字号会裁切 | 用 `sizeHint()/minimumSizeHint()` 与 stretch |

## 3. Performance Blueprint

### 3.1 Web 指标 → 桌面等价指标

| Web 指标 | 本项目指标 | 目标 | 度量方式 |
|---|---|---|---|
| LCP < 2.5s | 打包 exe 冷启动到可交互 | **≤3.5s**（本项目口径；见 3.2） | `health_check` 新增 `smoke_ms`；3 次取中位数 |
| INP < 100ms | UI 线程单次操作耗时 | ≤100ms；重排 p95 ≤16.7ms | `bench_resize.py`、`bench_g70_ui.py` |
| CLS < 0.1 | 首帧后 500ms 内无用户操作的控件位移次数 | 0 | `bench_resize.py` 的 `late_moves` |
| 60fps 动画 | 动画帧间隔中位数 | ≥30fps（本项目只有 3 处短动画） | 动画期 `paintEvent` 计数（新增时） |
| 资源优化 | QSS 构建时间 / 控件数 | QSS 首次 ≤5ms；不新增逐行子控件 | `bench_g70_ui.py` |

### 3.2 当前实测（2026-11-10）

| 项 | 实测 | 判定 |
|---|---|---|
| `scripts/bench_startup.py` | Qt import 20.0ms / UI import 83.1ms / ctor 124.3ms / first frame 17.9ms / total 250.9ms | ctor 比 120ms 诊断预算高 4.3ms，属噪声；总路径 251ms，不是用户瓶颈 |
| `scripts/bench_resize.py` | 8 尺寸 × 3 字号；最差 9.0ms @1020×584；`over_budget=[]`；`late_moves=0` | 已达标，不需要优化 |
| `scripts/bench_g70_ui.py` | 500 行 add 23.64ms / update 1.49ms / progress_widgets 0；QSS 9,280 字符，首次 2.229ms、缓存 0.013ms；空库启动 109.42ms | 已达标；QSS 9,000 字符旧目标可退役 |
| 启动冒烟（本次实测） | onefile：1,991 / 1,981 / 2,500ms；portable：2,483 / 2,509 / 2,528ms | 中位数 1.99s / 2.51s，**已低于 3.5s** |
| `health_check.elapsed_ms` | 5,844ms | **不是启动耗时**：包含 42.8MB exe + 82.2MB zip 的 SHA-256、版本提取与检查；不能拿来宣称“启动 5.8 秒” |
| `health_check` 的 note | “alive after 60s” | 是等待上限文案，不是实际耗时；应改成实际 elapsed |

### 3.3 必须修的是度量，不是启动代码

`health_check.py` 的 `elapsed_ms = time.perf_counter() - started` 从 `main()` 一开始计时，包含：

1. `artifacts_exist`；
2. 两个大文件的 `_sha256_chunked()`；
3. `_artifact_version()` 打开 PyInstaller 归档；
4. 最后才 `_run_smoke()`。

所以历史上把 `elapsed_ms=4034` 解释成“exe 启动 4 秒”是错误归因；真实启动冒烟只有约 2–2.5 秒。Rev14 `R14-17` 因此被 CUT（构造段仅占约 3.8%），这个 CUT 的**方向是对的**，但依据的数字来源错了。

修订方案：

- `_run_smoke()` 返回 `(started_ok, db_ok, note, smoke_ms)`；`smoke_ms` 从 `Popen` 前到检测到 `repos.db/settings.json` 或进程存活为止。
- `health_check` JSON 同时输出 `smoke_ms` 与 `total_ms`；`elapsed_ms` 保留为兼容字段，但文档明确它是总检查耗时。
- note 里写实际 `smoke_ms`，不再写固定的 `wait_s`。
- 发布门禁用 `smoke_ms`，不要用 `elapsed_ms`。

**不做**：

- 不做设置页懒加载（ctor 124ms，收益不可感知；会破坏大量“控件存在性”测试）。
- 不做主题切换优化（实测 42–50ms，低于 80ms 目标）。
- 不做 QSS 压缩（9,280 字符、2.2ms 构建，不是瓶颈）。
- 不引入缓存层/预热/启动画面（没有证据表明用户感知到 250ms 的 Python 路径）。

### 3.4 Qt 语境下的 lazy loading / code splitting / 资源优化

- **懒加载唯一候选**是设置页首次切换时构建；但 ctor 124ms、设置页控件存在性被大量测试依赖，收益小于回归面，**CUT**。
- **代码分割**在 PyInstaller 下没有 Web bundler 的意义；按模块边界拆文件是为了可维护性，不是为了启动。
- **表格批量更新**继续使用 delegate 自绘，不引入逐行 `QProgressBar`；`progress_widgets == 0` 是硬约束。
- **主题切换**只重刷 QSS，不重建控件；`QSS_CACHE` 已有，保持。

### 3.5 离线与优雅降级

现有：

- `app/errors.classify_error` 是唯一错误分类器；
- `app/retry_queue` 持久化 + 退避 + jitter；
- `ui/offline_indicator` 连续 3 次网络类失败显示断网标记；
- 状态条与失败面板就近提示。

本计划**不新增 Service Worker / 离线缓存**。只补一项：离线指示在恢复后 1 个事件循环内消失，且有 `accessibleName`；现有测试已覆盖，保持。

### 3.6 性能陷阱

| 陷阱 | 说明 |
|---|---|
| 把 `health_check.elapsed_ms` 当启动时间 | 已实际误导过 Rev13/Rev14；必须拆 `smoke_ms` |
| 为 4ms 的 ctor 超标写优化 | 用户感知不到；会引入懒加载回归 |
| 给几百行表格加 `QGraphicsDropShadowEffect` | 每项一个图形效果，滚动掉帧；现有 1px glow 已足够 |
| 把 QSS 目标从 9,000 改成更低 | 没有用户收益；构建 2.2ms，不值得 |
| 用 `QTimer` 轮询做动画 | 与 Qt 动画框架重复；现有 `QPropertyAnimation` + token 已够 |

## 4. Design System Specification

### 4.1 Token 架构：单一来源，按消费点扩展

现有唯一来源：

| 关注点 | 文件 | 内容 |
|---|---|---|
| 色板 | `gcm/ui/palettes.py` | 4 套主题 + 6 强调色 + 对比度工具 |
| 尺寸/间距/圆角/行高 | `gcm/ui/palettes.py::TOKENS` | radius / spacing / border / shadow / row |
| 排版 | `gcm/ui/typography.py` | 7 级 `TYPE_SCALE` + 字族栈 |
| 动效 | `gcm/ui/motion.py` | 220 / 180 / 600 / 120ms + OutCubic |
| QSS | `gcm/ui/qss_build.py` | 由色板 + token + 排版生成，带缓存 |

规则：

1. 每个 token 叶子必须**有生产消费点**，或在 `DELIBERATELY_UNUSED` 明确登记“刻意不提供”；`test_rev14_feedback.TestTokensHaveNoDeadEntries` 已守。
2. 不新增“看起来完整但没人读”的 spacing 档位；新增 `spacing.section = 24` 必须同时被 `settings_workspace` 或 `manage_table` 消费。
3. 组件不得再写死色值；需要新色时先加到 `PALETTES` 并跑 24 组对比度矩阵。
4. `theme.current_palette()` 是所有自绘路径（delegate / 日志高亮 / 托盘 / 状态 pill）的唯一颜色来源。

### 4.2 颜色策略

| 主题 | 定位 | 关键色 |
|---|---|---|
| `deep`（默认） | Ink 墨黑 + 骨白 + 示波器青 | `bg #0b0e10` / `text #e8e3da` / `accent #35c8b4` |
| `light` | Paper 暖纸 + 墨字 | `bg #f4f0e8` / `text #16191b` / `accent #0f7c70` |
| `nord` | 北欧低饱和 | `bg #2e3440` / `text #d8dee9` |
| `hc` | 高对比 AAA | 纯黑/纯白 + 高亮语义色 |

强调色 6 档：`teal` / `blue` / `violet` / `cyan` / `indigo` / `magenta`；深底取 `dark`、浅底取 `light`，成对存在。硬约束：

- 正文、弱文本 ≥4.5:1；输入边界 ≥3:1；`on_cta/cta` ≥4.5:1；`hc` 文本 ≥7:1。
- `accent` 只表达“正在发生”（进度 chunk / 焦点环 / 运行中 pill），**不用于静态装饰**。
- 每屏至多 1 个 `panel_primary` 卡面。
- 不改现有色值；任何改动必须重跑 4 主题 × 6 强调色 = 24 组矩阵。

### 4.3 间距、圆角、阴影

| Token | 值 | 用途 |
|---|---|---|
| `spacing.xs` | 4 | 图标与文字、紧凑行内 |
| `spacing.sm` | 8 | 控件间距、表格单元格 |
| `spacing.md` | 12 | 卡片内边距、分组间距 |
| `spacing.lg` | 16 | 页面左右 gutter、区块外边距 |
| `spacing.section`（新增，需消费） | 24 | 设置页大分组之间、页面级 section |
| `radius.card` | 6 | 分组卡、面板 |
| `radius.control` | 5 | 输入框、按钮 |
| `radius.bar` | 5 | 进度条、齿条 |
| `radius.tab` | 8 | 页签容器 |
| `radius.checkbox` | 4 | 复选框/单选 |
| `border.default` | 1 | 常规描边 |
| `border.focus` | 2 | 焦点环 |
| `shadow` | 不提供实际阴影 | 用 1px `glow` 顶边 + 边框表达层次 |

**间距哲学**：4pt 网格；新/改组件只使用 4/8/12/16/24；现有代码里的 6/10/14 **不批量替换**——它们分布在 64 处，批量改会造成像素回归，只在被本计划触碰的组件里顺手收敛。`QSS` 没有 `box-shadow`/`transition`，不要假装有。

### 4.4 排版

| 角色 | px @1.0 | 字重 | 字族 | 用途 |
|---|---:|---:|---|---|
| `display` | 28 | 600 | Bahnschrift | 批次结论大读数 |
| `h1` | 20 | 700 | Bahnschrift | 页面/对话框标题 |
| `metric` | 18 | 600 | Bahnschrift | 统计卡数值 |
| `h2` | 15 | 600 | 正文字族 | 分组标题 |
| `body` | 13 | 400 | Microsoft YaHei UI | 正文 |
| `mono` | 12 | 400 | Cascadia Mono | URL/路径/时间/计数 |
| `small` | 11 | 500 | 正文字族 + 0.5px 字距 | 铭牌、辅助说明 |

- 只使用系统内置字族；不打包 ttf、不联网下载。
- `QSS` 的全局 `QWidget { font-size }` 会覆盖 `apply_type()` 的 `QFont`；**不要在不改 QSS 的情况下给普通 QLabel 调 `apply_type()` 期待字号变化**。需要角色字号时用 `QLabel#pageTitle / #display / #metric / #kicker / #monoLabel / #small` 等 objectName。
- 正文行高由布局间距控制，不写 `line-height`（QSS 不支持）。

### 4.5 动效

| Token | 值 | 用途 |
|---|---:|---|
| `FAST_MS` | 120 | 微反馈预留（当前未消费） |
| `PULSE_MS` | 180 | 终态脉冲 |
| `BASE_MS` | 220 | 状态切换（进度条填充） |
| `SLOW_MS` | 600 | 行完成消隐 |

- 统一缓动 `OutCubic`。
- `prefers_reduced_motion=True` 时：QSS 去掉 hover/pressed 块，所有 `QPropertyAnimation` 跳过；这是现有行为，保持。
- **不新增 400ms 模态动画**：桌面工具需要即时感；若将来加对话框淡入，用 180ms，不用 Web 常见的 400ms。
- 不做 shimmer；骨架屏静态占位，减少动效时整块可关。

### 4.6 图标与插画

- 16 个语义 `QStyle.StandardPixmap` 映射；尺寸 16/20/24。
- 新增品牌图标：单色 `QPainter` 路径，颜色读 `current_palette()`，不引入 SVG/PNG 资源包。
- 禁止字符符号 `✓ ✕ ⚠ ⊘`：微软雅黑缺字形，会渲染成 tofu（G74 真事故）。
- 状态用 `status_pill.draw_shape` 的几何形状；形状互不相同才色盲可辨。

### 4.7 组件规则

| 组件 | 规则 |
|---|---|
| 主按钮 | 每屏最多 1 个 `#primary`；桌面最小高 38，触摸 44 |
| 次按钮 | `#secondary` 用于取消/暂停/有替代路径的动作 |
| 低频按钮 | `#ghost` 用于工具行、行内操作 |
| 危险按钮 | 只描边不填红底；默认按钮必须是 No |
| 分组卡 | `QGroupBox` 标题 h2 15px；`panel` 底；`radius.card` |
| 表格 | 表头 13px；行 26/28/34；数字列 mono 右对齐；选中 `accent` 12%/18% alpha；hover `panel2` |
| 空态 | 只走 `build_empty_state`；标题 h2、提示 small；过滤空态与真为空文案不同 |
| 对话框 | 最大 90% 宽 / 85% 高；最小 460×320；`apply_parent_theme`；破坏性默认 No |
| 日志 | `Cascadia Mono` 12px；最多 4000 block；关键字过滤显示层，不清模型 |
| 状态 pill | 7 种形状；颜色 + 形状双编码；不用字符 |

### 4.8 遗留组件调整

- `ManagePanel` 每行「查看」按钮保留：它是明确入口，改成悬停才出现会降低可发现性；只统一为 `#ghost`、13px，不新增第二种行内按钮风格。
- `settings_panel` / `settings_groups` 的 6/10 间距不批量改；只在新拆出的 `settings_workspace` / `log_panel` 中用 token。
- 旧 `QMessageBox.warning` 不强行全换成 `ErrorDialog`：只有需要“动作按钮 + 关闭”双语义的地方才用 `ErrorDialog`；纯提示保留原生，避免过度包装。

### 4.9 设计系统陷阱

| 陷阱 | 避免方式 |
|---|---|
| 新增 token 没消费点 | 先写消费点再登记；`DELIBERATELY_UNUSED` 只放真正无法消费的项 |
| 自绘颜色绕过 `current_palette()` | 所有 delegate/日志/托盘统一读它 |
| 用 `QGraphicsDropShadowEffect` 做卡片阴影 | 滚动列表掉帧；用 1px glow |
| 全局 QSS 字号覆盖角色字体 | 用 objectName 选择器；不在普通 QLabel 上迷信 `apply_type()` |
| 改色不跑对比度 | 24 组矩阵全绿才允许提交 |

## 5. UX/UI Pattern Library Plan

### 5.1 层级与可扫视性

当前信息层级基本成立：

- 顶部：全局状态条（并行进程/成功/失败/用时）；
- 页签：下载中心 / 仓库管理 / 设置与日志；
- 页面内：分组卡 → 行标签 → 控件；
- 主操作：下载页开始按钮、管理页一键更新、设置页即时保存。

需要修的只有设置页：日志与设置 1:1 让“设置”这个主任务被日志抢走一半高度。修完后的层级是：

```
设置页（主任务）
├─ 设置导航/搜索        ← 固定，不随内容滚走
├─ 设置分组（72%）      ← 主任务
└─ 日志（28%，可折叠）   ← 辅助排障
```

**不新增页面大标题**：三页签本身就是一级导航；再加一条“页面标题 + 副标题”会挤占 40–60px，违背矮窗优先原则。

### 5.2 反馈与可操作性

| 场景 | 现状 | 计划 |
|---|---|---|
| 点击开始到第一行结果 | `SkeletonRows` 骨架 + 空态互斥 | 保持；补 900×480 截图 |
| 长操作（诊断包/报表/备份） | `busy()` 禁用按钮 + 事件 | 保持 |
| 表格行 hover/选中 | 已有 | 保持 |
| 错误 | `ErrorDialog` + `classify_error` | 保持；破坏性确认默认 No |
| 设置保存 | 即时保存，无全局提示 | **不新增 toast**：设置项本身即时生效，状态条再加“已保存”会制造噪音；只在失败时用 `ErrorDialog` |
| 离线 | 断网标记 | 保持；恢复即消 |
| 目录大小计算 | “计算中…”占位 | 保持 |

### 5.3 导航模式

- **一级导航**：`QTabWidget` 三页签（下载/管理/设置），`Ctrl+1/2/3` 直达，`F6` 循环。
- **二级导航**：设置页左侧分组列表；`<1000` 宽改为下拉；设置搜索框可跨分组过滤。
- **命令面板**：`Ctrl+K` 搜索并执行任意功能；菜单「工具」有入口，帮助页列出快捷键。
- **面包屑**：不适用。三个一级页签 + 分组导航已足够；再加面包屑是重复信息。
- **底部导航/汉堡菜单**：不适用。桌面窗口没有移动端底部栏语义。

### 5.4 无障碍（WCAG 2.1 AA 最低）

当前真实状态：

- 主操作 14/14 有 `accessibleName` + `accessibleDescription`。
- `QPushButton` 57 个全部可读（Qt 默认取 `text()`）。
- 原始审计 `missing_total=25`，但其中 **19 个是 `QSpinBox` 内部 `QLineEdit`**、**4 个是 `QLineEdit` 的清除按钮**、**1 个是菜单栏扩展按钮**；真正缺名的只有 **ManagePanel 搜索框 1 个**。
- 现有基线 `scripts/a11y_baseline.json` 是 28，比当前 25 更松，且把内部控件算进去，导致“只降不升”棘轮失去意义。

计划：

1. `manage_search.setAccessibleName(tr("搜索仓库"))` + `setAccessibleDescription(tr("按仓库名、作者、标签或 host 过滤"))`。
2. `scripts/a11y_audit.py` 改为只统计**用户可操作的顶层输入控件**：
   - 排除 `QAbstractSpinBox` 内部的 `QLineEdit`；
   - 排除 `QLineEdit` 内部的清除 `QToolButton`；
   - 排除 `objectName == "qt_menubar_ext_button"`。
3. 基线更新为“真实缺名 = 0”；加一个反向自检：临时插入一个裸 `QLineEdit`，审计必须报 1。
4. 其他 AA 项：
   - 键盘可达：主操作可 Tab；设置 combo 进链；
   - 焦点可见：每类可聚焦控件 ≥1 条 `:focus`；
   - 对比度：24 组矩阵；
   - 减少动效：`prefers_reduced_motion` 全关；
   - 文字缩放：0.9–1.6，DPI≥150% 下限 1.0；
   - 破坏性确认默认 No。

### 5.5 表单与输入

- 仓库地址：300ms 防抖校验，显示“有效 N / 无效 M”，最多列 3 条无效行；不弹 `QMessageBox`。
- 设置项：`QSpinBox` 范围约束；`QComboBox` 选项完整；数值非法由控件自身拦截。
- 搜索框：`QLineEdit` + `setClearButtonEnabled(True)`；补 accessible name。
- **不做设备相关 input type**：桌面 Qt 没有 `inputmode`；数字框已用 `QSpinBox`。
- 表单错误就近显示；不要让用户从日志里找原因。

### 5.6 动效

- 只保留三处有意义的动效：批次进度填充 220ms、终态脉冲 180ms、行完成消隐 600ms。
- hover/pressed 用即时颜色（QSS 不支持 transition）；不要为了“丝滑”引入逐控件动画。
- `prefers_reduced_motion` 或 `animations=False` 时全部跳过。
- 禁止持续 shimmer；骨架静态。

### 5.7 空态、错误与权限边界

| 状态 | 现状 | 计划 |
|---|---|---|
| 表格无数据 | `build_empty_state` | 保持 |
| 过滤无结果 | `filtered=True` 文案不同 | 保持 |
| 准备期 | 骨架，不显示“没有仓库” | 保持 |
| 网络失败 | 失败面板 + 离线指示 | 保持 |

| 任务被跳过 | 状态 pill「已跳过」+ 计数 | 保持 |
| 关闭时有任务 | Yes/No 确认 | **默认 No**；Esc = No |

### 6.3 主题与 CSS 策略

- 唯一 QSS 产地：`gcm/ui/qss_build.py`；不引入 CSS modules / CSS-in-JS / Tailwind 类方案。

- `theme="auto"` 解析：
  - 增加 `resolve_theme_name(name)`：`auto` → `QStyleHints.colorScheme()`（Light/Dark/Unknown），Unknown 时回退 `app/system_theme.detect_system_light_theme()`；非 Windows 用 Qt API。

  - 连接 `QStyleHints.colorSchemeChanged` → 仅当设置为 auto 时重刷 QSS；用绑定方法，避免引用环。
  - 兼容旧行为：手动 deep/light/nord/hc 不走系统探测。
