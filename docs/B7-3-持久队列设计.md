# B7-3 设计稿：持久队列 + 调度时间窗（**只设计，未实现**）

> （新表 + 调度语义与既有 3 个后台任务互斥），约定**先出设计、不动代码**。
> 参考：`ab-download-manager` 的 `ScheduleTimes(daysOfWeek, startTime, endTime)`（见
> `参考的结果计划指南.md` §高价值参考项目）。

## 1. 要解决什么（先确认问题存在）

现状：批次是**一次性**的（粘贴地址 → 开始 → 结束）。用户真实用法是"挂着刷几百个仓库"，
需求是"**每天夜里 2 点把清单跑一遍**"。当前能凑合的手段及其缺陷：

| 现有手段 | 缺陷 |
|---|---|
| 手动再点一次 | 需要人在场 |
| 看门狗续跑 | 只处理**未正常完成**的批次，不是定时任务 |
| 定时报表 | 只生成报表，不同步 |
| 自动更新检查 | 只管检查版本 |

→ 结论：**"定时跑一批同步"确实缺失**，这不是"再加一个定时器"能解决的（要持久化队列 + 错过补跑 + 互斥）。

## 2. 数据模型（新表，schema v4）

```sql
CREATE TABLE IF NOT EXISTS sync_queue (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    name          TEXT NOT NULL,              -- 队列名（如「夜间全量」）
    specs_json    TEXT NOT NULL,              -- [{owner,repo,url_https,folder_name,ref,host}]
    days_of_week  TEXT NOT NULL DEFAULT '1,2,3,4,5,6,7',  -- 1=周一..7=周日
    start_time    TEXT DEFAULT '',            -- 'HH:MM'，空=不限
    end_time      TEXT DEFAULT '',            -- 'HH:MM'，空=不限
    enabled       INTEGER DEFAULT 1,
    on_missed     TEXT DEFAULT 'skip',        -- skip | run_once（错过窗口后是否补跑一次）
    last_run_at   TEXT DEFAULT '',
    last_status   TEXT DEFAULT '',
    created_at    TEXT, updated_at TEXT
);
```
迁移：`_SCHEMA_VERSION` 3 → 4，`_migrate` 里加 `CREATE TABLE IF NOT EXISTS`（幂等，与既有做法一致）。

## 3. 调度语义（必须先定死的 4 条规则）

1. **窗口判定**：`days_of_week` 命中当天 **且** 当前时间在 `[start_time, end_time)` 内 → 允许启动；
   两者都空 → 视为"随时可启动（退化为手动触发）"。
2. **错过补跑**：进程在窗口后才启动 → 按 `on_missed`：
   `skip` = 不补（默认，最不意外）；`run_once` = 立即补一次（**同一天最多一次**，用 `last_run_at` 判重）。
3. **与既有后台任务的互斥**：同一时刻只允许一个"批次来源"占用引擎：
   `手动批次 > 队列批次 > 看门狗续跑`；队列启动前必须检查 `engine.busy` 且
   **`report_scheduler` / `alert_scanner` 的运行不算冲突**（它们是独立线程，不占引擎槽）。
4. **不做静默重试**：队列只负责"到点启动一批"，失败项照旧进 `retry_queue`——
   避免出现"队列重试 + 重试队列重试"的双重重投（这正是 G67-3 修过的坑）。

| 步 | 内容 | 风险 | 验证 |
|---|---|---|---|
| S1 | `db/queue_db.py` + schema v4 迁移 + 单测（建表幂等 / 旧库升级 / CRUD） | L3（迁移） | 拿 v3 真库升级一次，断言旧数据完好 |

## 5. 明确不做（避免范围膨胀）

- 不做"依赖上一个队列完成"的 DAG 编排（那是工作流引擎的活）；
- 不做跨机器分发（本项目是单机桌面工具）；
- 不做队列内的优先级抢占（并发上限已由 `engine` 管）。

## 6. 回滚

迁移只**新增表**，不删列不改列 → 回滚只需删代码路径（老版本打开新库会忽略未知表）。
若出现数据问题：`DROP TABLE sync_queue` 即可回到 v3 语义。
