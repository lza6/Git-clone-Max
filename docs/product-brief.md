# Git-clone-Max 产品定位与增长 brief（2026-09-26 初稿；2026-10-13 校准）

> 版本号不写死在本文件：唯一事实源是 `gcm/__init__.py` 的 `__version__`。
> 落地进度看 `gcm/__init__.py` 的 `__changelog__`（逐版本登记）。

## 1. 产品定位
- **一句话**：面向「批量管理大量 Git 仓库」的桌面生产力工具——粘贴即批量克隆、一键增量更新、入库追踪、统计报表、agent 可调用。
- **形态**：PyQt6 桌面（Windows 优先，跨平台源码可跑）；CLI/MCP/HTTP API 作为 agent 接入面。
- **差异化**：小白可用的批量克隆 + 开发者/agent 可调用的结构化契约（--json/MCP/HTTP）。

## 2. 目标用户
| 用户群 | 场景 | 当前满足度 |
|--------|------|-----------|
| AI/Agent 开发者 | 批量克隆参考项目库、agent 技能库 | 高（--json/MCP/skills） |
| 半技术小白 | 收藏 GitHub 项目批量下载更新 | 高（向导/排错/一键） |
| 团队/知识管理 | 维护内部仓库镜像/归档 | 中（mirror/archive 已有） |
| 高校/教学 | 批量拉取学生仓库/教学素材 | 中（本地扫描/Star 导入） |

## 3. 核心功能边界（已交付 G51 → G67）

- 批量克隆/更新/镜像/归档/断点续传/弱网降级
- 入库追踪/标签/收藏/黑名单/统计/报表/评分卡/告警/企业 IM 推送（G59-7）
- 可靠性：重试队列/看门狗/跨会话续跑/失败聚合
- agent 面：CLI --json/--diag/--serve、MCP 只读、HTTP API（强制回环）、6 个 skills 技能包
- 安全与工程质量：契约版本单源、钩子命令注入防护、跨线程 Qt 信号化、浅仓增量更新修复、
  三平台 CI fast/slow 拆分（G59-5）、静态守卫测试（G66/G67）

> 精确到「凭什么算完成」的证据在 `docs/验证记录-*.md` 与 `docs/reports/`；
> 本文件只给产品视角的边界，不重复登记迭代细节。

## 4. 增长突破口（结构化头脑风暴，按 ROI 排序）
| 方向 | 动作 | 潜在收益 | 成本 |
|------|------|----------|------|
| **A. 生态接入**（推荐先做） | 把 skills/ 发布为可安装技能市场条目 + 完善 MCP 写操作（显式授权） | 吸引 agent 开发者成为传播节点 | 低 |
| **B. 自动化闭环** | 定时更新/告警 Webhook 推送到企业 IM（钉钉/飞书/企微） | 团队协作场景刚需 | 中 |
| **C. 数据资产化** | 批量克隆结果生成"项目知识索引"（README 摘要/标签自动分类） | 知识管理付费场景 | 中 |
| **D. SaaS 化远景** | 服务端多用户/共享仓库池（需架构演进，见 perf-observability） | 商业模式升级 | 高 |

**各方向现状（2026-10-13 校准）**：

| 方向 | 现状 |
|------|------|
| A. 生态接入 | **部分**：`skills/` 已有 6 个技能包、MCP 提供 `--allow-export` 报表导出；「可安装技能市场条目」与 MCP 写工具仍未做 |
| B. 自动化闭环 | **基本闭环**：定时报表（`sched_reports.py`）+ 企业 IM 推送（G59-7 钉钉/飞书/企微）+ Webhook **幂等去重 / 审计台账 / 失败重试**均已落地（v9.4.2–v9.4.6，见 `docs/验证记录-2026-10-17.md`）；仅「告警规则的可视化编排」未做 |
| C. 数据资产化 | 未做 |
| D. SaaS 化远景 | 未做（架构建议见 `perf-observability.md` §3） |

## 5. 用户留存抓手（体验层面）
- 首启向导 + 引导清单（G54-4）降低上手门槛
- 一键体检/排错地图让报障自助

- 失败聚合 + 看门狗减少挫败感
