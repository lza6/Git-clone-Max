## 1. 移除内置国内镜像（用户直接诉求："git 速度还是很慢 / 不需要国内镜像"）

### 1.1 修复前实测（同一仓库，干净临时目录，各两轮）

```bash
# 走内置镜像（当时的默认）
python -m gcm --cli --json --dir <tmp> urls.txt      # urls.txt = https://github.com/lza6/Git-clone-Max
# 直连源站
python -m gcm --cli --json --no-mirror --dir <tmp> urls.txt
```

| 模式 | 第 1 轮 | 第 2 轮 | 实际走的通道 |
|---|---|---|---|
| 内置镜像（**默认**） | **24,836 ms** | **24,398 ms** | `https://gh-proxy.com` |
| 直连源站 | **3,079 ms** | **2,971 ms** | direct |

**慢约 8 倍**。而且慢是结构性的：`_resolve_clone_url()` 会先对每个候选镜像跑一次
`git ls-remote`（每个最多 `mirror_probe_timeout=8s`），探完再走一个比直连更慢的第三方代理。

### 1.2 修复后实测（默认配置，三次）

| 轮次 | 耗时 | 通道 |
|---|---|---|
| 1 | 3,180 ms | direct（源站） |
| 2 | 3,525 ms | direct（源站） |
| 3 | 2,985 ms | direct（源站） |

### 1.3 改了什么

| 位置 | 变化 |
|---|---|
| `app/mirrors.py` | `DEFAULT_GITHUB_MIRRORS` → **空元组**（附实测证据与理由，永久移除而非"默认关"） |
| `db/settings.py` | `mirror_use_presets` 默认 `True` → **`False`**，标注为**已失效字段**（旧 settings.json 无损加载） |
| `app/engine.py` / `git/service.py` / `ui/engine_factory.py` / `app/worker.py` | 构造默认值 `True` → `False` |
| `cli.py` | 一律 `mirror_use_presets=False`；`--no-mirror` 保留为**兼容开关**（旧脚本仍在传） |
| `ui/settings_groups.py` / `settings_panel.py` | 移除「使用内置国内镜像」复选框与其保存回调；镜像输入框/回退开关/测速按钮保留 |
| `ui/main_window.py` | 删除对应的转发方法 |

**保留的能力**：用户自定义 `mirror_prefix`（按需自己填）· 「有凭据绝不走镜像」·「失败回退源站」。

### 1.4 守卫

- `test_g58_mirror_failover.test_no_builtin_presets_at_all` —— **钉死「预设必须为空」**（任何人填回去即红）

## 2. X-4：1366×768 笔记本上「保存清单 / 载入 / 导入 Star」被裁成空框

### 2.1 修复前实测（`visibleRegion` 几何断言，不是看截图猜）

| 窗口尺寸 | 来源 | 修复前 |
|---|---|---|
| 1240×729 | `clamp_window_size(1240,840, 1366,768)` = **1366×768 笔记本的真实窗口** | 三个按钮只露 **10px**（86×10 / 86×42），下拉框 6px —— 截图里就是四个**空框** |
| 1216×684 | `clamp_window_size(1240,840, 1280,720)` = 1080p@150% | **0×0，完全不可见** |

**为什么躲过了 4 轮 UI 迭代**：`scripts/ui_screenshot_audit.py` 出 34~38 张截图，
但**只存图、不断言**。`isVisible()` 对被父级裁掉一半的控件仍返回 True。

### 2.2 修法（不是补 padding，是搬位置）

| 步骤 | 内容 |
|---|---|
| ① | 清单行从 `build_download_top()` 的最后一行**搬出**滚动区 → 新函数 `build_task_list_row()`，与主操作行并列常驻（与 G74 把「开始/取消」搬出滚动区同一判断） |
| ② | 动作区（现在 3 行）纵向策略钉 `Fixed` 并按**真实** `sizeHint` 设最小高度（构建时 sizeHint 未定型 —— G78 为 chip 踩过同一个坑） |
| ③ | 矮窗口让**可滚动**的顶部区让位：`<640px` 时最小高 180→120→**64**，而不是切掉常驻按钮 |

> 第 ②③ 步是修 ① 时**新暴露**的问题：搬进来后总共三行，在声明的最小窗口 1020×560 下
> Qt 把动作区压成 31/42px —— 也就是"把裁切从一处挪到另一处"。全尺寸复测才发现。

### 2.3 修复后实测（9 个尺寸全部零裁切）

| 尺寸 | 含义 | 结果 |
|---|---|---|
| 1920×1080 / 1440×900 / 1366×768 / 1280×800 | 常见桌面 | ✅ 0 裁切 |
| **1240×729** | 1366×768 笔记本（事故现场） | ✅ **0 裁切** |
| **1216×684** | 1080p@150%（原 0×0） | ✅ **0 裁切** |
| 1093×614 | `layout.py` 声明的目标（1366×768@125% 工作区） | ✅ 0 裁切 |
| 1024×768 | 老式 4:3 | ✅ 0 裁切 |
| **1020×560** | `WINDOW_MIN`（极矮，最易压扁） | ✅ **0 裁切** |

截图证据：`reports/ui-v9121-check/download_laptop1366_1240x729.png`（清单行完整可见，位于主操作区）。

### 2.4 守卫（含变异自检）

`tests/test_ui_compact_visibility.py`（3 例）：
1. **9 个尺寸逐个**断言 `visibleRegion == rect`（不只是 `isVisible()`）；
2. 反向自检：两个「笔记本尺寸」必须**真的**等于 `clamp_window_size` 算出来的值（防止有人把它改成宽松尺寸让守卫失去意义）；
3. **变异自检**：把某个控件 `setParent` 回滚动区内容里 → 守卫**必须红**（证明它真能抓住 X-4）。

## 3. X-5：英文模式下 72 处文案回落中文

### 3.1 修复前实测

```
ZH=494  EN=494  使用中的字面量键=436  缺=72
```

ZH/EN 键数**对称**（所以从来没人怀疑），但**在用的 72 个键根本不在字典里**；
`tr()` 的兜底是 `return key` → 英文模式下原样显示中文。其中包含
「保存」「确定」「搜索设置项」「黑匣子日志」这种到处都是的常用词。

### 3.2 修法

| 步骤 | 内容 |
|---|---|
| ① | 补齐 72 个键：zh 用 key 本身；en **逐条英文翻译**（长 tooltip 也翻了，不留占位） |
| ② | 新增 `scripts/i18n_coverage.py`：三条断言（键在 ZH 且在 EN / 两表键集合相等 / **含中文的键其 EN 值不得再含中文**） |
| ③ | 新增 `tests/test_i18n_coverage.py`（4 例，含"扫描器不是空转"的反向自检） |

第三条断言是关键：只查"键在不在"会漏掉**占位未翻译**（值 = 中文 key），
而那在英文模式下**等价于回退**。

### 3.3 修复后实测

```
ZH=566  EN=566  使用中的字面量键=436  缺=0   →  I18N OK
EN 中仍是中文的键数 = 0
```
