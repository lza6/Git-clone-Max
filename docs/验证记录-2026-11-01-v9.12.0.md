## 4.6 跨重启闭环实测 —— 抓到第二个伪闭环（**单测全绿也漏掉的那类**）

第 4 节的单测都改的是**运行中**引擎（走 `_launch` → `engine_factory`）。为验证真实用户路径，
补做了一次「改设置 → 关窗 → 重新构造 MainWindow（等价重启）」的实测：

```
[1] 改后引擎: 11  1200.0
[磁盘] host_concurrency=11 / time_budget_min=20   ← 落盘正确
[2 重启] 引擎: 4  0.0      ← ❌ 引擎仍读默认值
[2 重启] 控件回填: 11  20   ← 界面却显示正确
```

**根因**：`MainWindow.__init__` 里**手写着第二份** settings→engine 参数列表（G45 时代遗留），
与 `engine_factory.build_sync_engine` 那份慢慢漂移，漏掉了
`host_concurrency` / `time_budget` / `concurrency_state_path`。
界面从 settings 读（所以回填对），引擎从那份漏项列表读（所以是默认值）。

**修法（治根，不是补一个参数）**：启动期也走 `build_sync_engine`，删掉手写列表 →
settings→engine 变成**唯一映射点**；`MainWindow.__init__` 顺带 -19 行（`__init__` 252 → 240 行）。

**新增的三条副作用控制**（避免「修一个 bug 引入两个」）：
1. `build_sync_engine(..., enable_retry_queue=False)` 给**启动期空闲引擎**用 ——
   启动时 `_last_batch_ctx` 为空，若挂上重投队列并自动重投，会把非 GitHub 仓库
   落库成 `host="github.com"`（G67-3 修过的同类污染）。真批次引擎仍默认 True。
2. `host_concurrency` / `time_budget_min` 走工厂后启动即生效（真机复验：闸门容量 = 11）。
3. `concurrency_state_path` 走工厂后，启动即恢复上次并发（C1-9 端到端：记忆 3 / 天花板 8 → 引擎 3/8）。

**守卫**：`TestStartupEngineReflectsSettings`（4 例）——启动路径读持久化值、空闲引擎无重投队列、
批次引擎有重投队列（对照组）、启动恢复并发记忆。

> **教训（写进 decisions D39）**：同一个「设置 → 消费方」映射存在两份实现时，
> 单测永远只覆盖它碰巧走过的那一份。这类缺陷只能靠「按真实用户路径（含重启）走一遍」发现。

### 8.3 Suggestion（采纳 6 条，登记 2 条）

- ✅ `doc_drift_check` 在中文 Windows（cp936）下打印 `✓/✗` 会 `UnicodeEncodeError` —— 而它唯一用途就是在**有漂移时**打印这些行。已 `sys.stdout.reconfigure(encoding="utf-8")`。

### 8.4 审查轮自身的一个反转（值得单独记）

C-2 的**第一版修法是错的**，而且是全量快集抓出来的：

```
FAIL: test_retry_tick_without_prior_batch_still_works
      (tests.test_g67_closure.TestRetryReusesBatchContext)
```

该用例的 docstring 写得很清楚：「快照为空时**不得崩**（首次启动即有待重投队列的边界场景）」，
并断言 `launch` 会被调用、`host_by_key == {}`。也就是说，「无上下文也允许重投」是**既有契约**，
我用一行 `if not self._last_batch_ctx: return` 把它关掉了 —— 属于「修一个 bug，废掉一个特性」。

**正确的修法**是回到根因：污染不在重投，而在 host 的取值方式（`or "github.com"` 盲回落）。
改成 `_host_for()`（登记表 → URL 解析 → 回落）后，既保住了重投契约，又消除了污染源。
