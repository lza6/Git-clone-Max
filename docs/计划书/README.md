> `docs/data-model.md` / `policy.md` / `test_ledger.md` / `workflow_status.md` / `.agent/memory/`。

## 1. 目录纪律（来自 `policy.md` §5 与 `.agent/skills/plan-doc-audit.md`）

1. 本目录的文档**有生命周期**：条目全部闭环并**逐条复验**后 → 归档到
   `docs/archive/plans/<YYYYMMDD>/` + 写 `archive-manifest.md` → 才可删除。
2. **存在任一未闭环 / 需用户决策项时不得删除**。历史教训：本项目的 `计划书/`
   曾以「全部闭环并经用户确认」由删除，2026-10-16 独立复验推翻了该理由
   （定时报表零调用点、告警未接线、9 个设置字段不可达）。
3. **文档里的 ✅ 不等于代码里做了**。判定只看三样：生产调用点（不是测试引用）、
   UI 入口三段是否通（控件 → 保存回调 → 消费方）、本轮真实运行输出。
4. 删除前必须查死链并跑文档守卫：`./.venv/Scripts/python.exe -m unittest tests.test_g67_docs_freshness`
   （该守卫扫描 `docs/**/*.md`，会检查路径是否存在、版本号是否与 `gcm.__version__` 一致）。

## 4. 怎么写这类文档（最小要求）

- 每条改进项必须带：**证据（file:line 或命令输出）· 判定标签（已验证/静态确认/合理推断/待验证）· 验收方式 · 回滚方式**。
- 涉及运行时验证的，写成「待执行验收项」（命令 + 预期 + 证据要求 + 回滚），**不得**写成已完成。
- 不复制其他文档的事实（避免两份真相漂移）；只写指针。
