Git-clone-Max G71 变更报告

日期：2026-10-19 · 版本：v9.8.0 · 范围：队列可观测性 / SSE 事件流 / 三段式错误 / 诊断包 / 长函数拆分

1. 为什么做这次变更

对标参考项目 SurgeDM/Surge（MIT）与 amir1376/ab-download-manager（Apache-2.0）暴露的四类差距：

  • 任务从排队到终态只活在 UI 信号里，agent 与诊断拿不到结构化执行轨迹；
  • 失败重试是黑盒，用户看不到次数、下次时间、原因，也无法立即重试/放弃；
  • 错误只有一句 git 原文，缺少「发生了什么 / 为什么 / 怎么办」与可重试判定；
  • 持久化 tmp 写法不统一，诊断材料靠截图/多段文本。

2. 关键决策

决策理由
进程内 EventBus + 有界缓冲单机桌面工具无常驻服务端；发布永不阻塞/抛出，慢订阅者丢最旧并计数。
SSE 由 GUI 进程托管（设置页，默认关、仅回环）独立 --serve 与 GUI 是两个进程，EventBus 不互通；同进程托管才能看到真实引擎事件。
错误是否可重试只由 app/errors.classify_error 判定避免「重试队列认为可重试、UI 显示另一类」的双份关键字表。
所有 JSON 持久化走 write_text_atomic唯一 tmp + fsync + 目录 fsync + 替换退避；并发不互相截断。
长函数按「纯映射/纯构建」拆分_update 337→105、_launch 153→124、下载页构建 191→35，行为零变化。

7. 风险与回滚

  • EventBus 非持久；跨重启审计依赖 app.log/progress.json。
  • SSE 无鉴权，只绑回环 + Host/Origin 校验；事件已打码，不得经无鉴权反代暴露公网。
  • 独立 --serve 看不到 GUI 事件，需用设置页托管。
  • 回滚：所有改动均为本地源码/文档；git checkout -- . 可整体回滚（版本号与 changelog 同步回退）。

8. 小测验

1. 为什么独立 --serve 收不到 GUI 的 SSE 事件？

EventBus 是进程内单例；两个进程内存不互通。需在设置页开启「本地 API / 事件流」由 GUI 进程托管。

2. 哪些错误可自动重试？

网络/超时/429/5xx。401/403/404、磁盘满、平台限制不可自动重试。

3. 同一仓库 @v1 与 @v2 同批，状态机用什么 key？

folder_name（含 @tag），不是 owner/repo。

4. 诊断包为什么不包含 settings.json？

settings 含加密凭据；诊断包只放已打码文本（报告/事件/日志尾部）。

5. 原子写为什么需要唯一 tmp 名？

固定 tmp 名在并发写时会互相截断，导致保存丢失/非法 JSON。
