变更报告 — Rev14：跨设备适配 / 无障碍 / 反馈闭环 / 发布台账

日期 2026-11-06 · 版本 9.18.8 · 基线 main @ f6b913e + 工作区

1. 上下文：为什么做这次变更

这个仓库是 PyQt6 桌面单机工具（批量并行克隆 GitHub/GitLab 等仓库），不是 Web 应用。 上一轮已经把「跨设备适配 / 性能 / 设计系统 / UX」拆成了 Rev14 施工版，本轮做三件事： ①用户拍板的三项修复落地；②独立审查提出的问题收口；③把「修好了也看不见」的验收基础设施补齐， 并把发版台账（9.18.8 的 changelog 条目）聚合出来。

模板里适配 Web 的条目（断点 320/768px、LCP/INP/CLS、Service Worker、dvh/刘海、CDN/Redis/分片/热更新） 按项目真实形态做了同构替换或判定不适用 —— 这个产品没有服务端，policy.md §4 明确 「热更新不适用于本项目，不得虚构服务端部署流程」。

2. 直觉：关键决策与取舍

决策取舍
「下载位置/克隆模式」移出滚动区 实测小屏被裁到 6–23px（target_edit 352×6/352×34）。移出后顶部常驻区 +140px， 折叠阈值必须从 580 抬到 720/740/760（逐 10px 重扫），代价是最小窗口上要折叠工具行 —— 这是设计好的降级。
跳过的仓库用 skipped 信号回报 不动 CLI 的 results[]/退出码契约（GUI 传 True、CLI 默认 False）。因为 index 是「调度序」而非「输入序」， 被跳过的 spec 没有 index，只能用 owner/repo 作 key 去找行。
像素基线用当前状态重拍并 gitignore 旧基线是 Rev11-final，比出来 28 张、30%+ 差异全是菜单栏带来的整体位移 —— 那种"全红"会让人重新忽略这个护栏（历史事故）。
不做页面级标题 加了要吃掉约 30px，正好抵掉本轮争来的高度（最小窗口会重新裁按钮）。页签本身已经给出页面身份，收益小于回归风险。

4. 链路图

用户点「开始」
   └─ MainWindow._launch
        ├─ _prepare_table(len(specs))      ← 必须先建行（setItem 对不存在的行是空操作）
        ├─ _add_table_row(i, spec)          ← 预填占位行（等待中）
        └─ engine.launch(specs, report_skipped=True)
             ├─ _dedupe_specs(key=目录名)
             ├─ _precheck_skip(spec)        ← 命中：已完成 + 目录在
             │     ├─ _mark_done("owner/repo")      ← key 口径统一
             │     └─ skipped.emit("owner/repo", 说明)
             │           └─ MainWindow._on_engine_skipped → 行变「已跳过」
             └─ 未命中 → worker → result(index, res)
                   └─ _on_worker_result → 行终态 + 耗时(duration_ms)

批次结束 → progress_table._on_engine_finished
   ├─ 统计 UserRole（success/failed/conflict/skipped）
   └─ batch_finish.announce_finished(owner, ...)  → 状态栏 / 日志 / 托盘 / Webhook

6. 风险与回滚

项回滚方式
布局重排（选项行常驻 + 折叠阈值 720）git revert 对应提交；download_layout.build_download_options 是纯新增函数，删掉即可回到旧结构

7. 已知限制

  • 真机多屏 / 拔插 / 混合 DPI 未验：本机单屏，只覆盖注入屏幕参数的纯函数 + 离屏 4 档缩放。
  • 屏幕阅读器（NVDA/JAWS）实机未验：只保证「名称/角色/顺序/焦点/对比度」五项静态可验证。
  • 首帧后 500ms 内有 31 次控件位移（CLS 等价，目标 0）：来源是 show 后 150ms 的布局去抖重算，未修。
  • 离屏 800×800 在 2.0 缩放档只剩 400×400 逻辑尺寸，低于项目声明的 ABSOLUTE_MIN 900×480 —— 属 "unsupported"，不是回归。
  • 打包 exe 与真机点击未验：属发版动作，需 health_check.py --json。

8. 测验

  1. （选择）被断点续传预检跳过的仓库，为什么用 owner/repo 而不是 index 回报给 UI？
    A. 因为 index 是调度序，被跳过的 spec 没有 index　B. 因为字符串更省内存　C. 因为 UI 只认字符串

    答案 A。

  2. （判断）把「下载位置/克隆模式」移出滚动区后，折叠阈值可以保持不变。
    错。顶部常驻区 +140px，阈值必须从 580 抬到 720/740/760，否则工具行被裁。
  3. （简答）progress_rows.install_row 为什么在「预填行」时是空操作？
    答案：它只用 QTableWidget.setItem(index, col, item)，而 Qt 对不存在的行是静默忽略， 不会自动扩容。必须先 setRowCount（即 _prepare_table）。
  4. （选择）全快集修复前的 3 条红灯是什么？
    A. 单元测试逻辑错　B. __version__ 已 bump 到 9.18.8 但没有 changelog 条目　C. 编码问题

    答案 B。

  5. （判断）pixel_diff 的阈值宽到 2px 位移也发现不了，仍然算有效护栏。
    错。所以它自带 --self-check：平移 2px 必须报警（实测占比 1.11% > 阈值 0.5%）。
  6. （简答）为什么 effective_name 不能用 QSpinBox.text() 当无障碍名字？
    答案：它返回的是**当前数值**（如 7），不是标签；同样 QLineEdit.text() 是用户输入。 把它们当名字会让审计永远认为"有名字"，棘轮对新加的无标签输入框失明。
  7. （选择）折叠态下最先让位的是谁？
    A. 主操作按钮　B. 进度表与它的筛选行　C. 输入框

    答案 B。常驻按钮被裁才是真缺陷；可滚动区先让位。

  8. （判断）把「页面级标题」加回去没有代价。
    错。要吃掉约 30px，最小窗口下会把本轮争来的高度抵掉，按钮重新被裁。
  9. （简答）settings.ui_state 为什么必须写读两侧都接线？
    答案：只写不读 = 用户改了没用（项目红线 TestG69_18WiringClosure 会抓）；只读不写 = 永远默认值。
  10. （选择）本项目的"部署"等价动作是什么？
    A. 推 Docker 镜像　B. 打包 → health_check 真启动 → GitHub Release　C. 热更新服务端

    答案 B。policy.md §4：桌面单机工具，没有服务端，不得虚构热更新流程。
