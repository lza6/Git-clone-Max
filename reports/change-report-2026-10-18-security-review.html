审查的价值不在于证明我做对了，而在于在用户之前发现我做错的地方。

一、两个阻塞问题

#问题后果
1镜像克隆把 origin 固定成镜像地址；之后用户配 token，fetch 的全局 http.extraHeader 会被发给镜像 凭据泄漏 GitHub PAT 发给第三方
2QPushButton.clicked 会传 checked=False，而槽不接受参数 按钮必崩 「测速并排序」完全不可用
为什么自测没发现第 2 个：
我的 UI 测试都是直接调面板方法，绕过了按钮的 signal → 这正是本项目反复警告的 「测试绕过 UI 链路」。修复后补了一条真实点击的测试。

二、凭据修复：不是改注释，是改作用域

# 修复前（全局头：所有 HTTP 请求都带）
http.extraHeader = Authorization: Bearer <token>

# 修复后（URL 作用域：只对匹配源站的请求生效）
http.https://github.com/.extraHeader = Authorization: Bearer <token>

再配合三条硬约束：

约束作用
镜像克隆成功后 remote set-url origin <源站>origin 永远是源站；镜像只记在 gcm.mirror
旧仓库更新时自动规范化 origin历史遗留的镜像 origin 会被自愈
全局/系统 http.*extraHeader 存在 → 禁用镜像用户自己的 git 凭据也不会被发出去
真实实验（不是推断）：
本地 HTTP 服务记录请求头：
· 源站 URL 匹配作用域 → Authorization: Bearer ghp_SECRET（确实发送）
· 跨 host 镜像 URL → None（收不到）
· 探测路径（全局 gitconfig 带 extraHeader）→ None

三、复验轮又抓到 3 个 HIGH

发现修法
测速路径绕过「全局认证头 → 禁用镜像」守卫测速前调用同一守卫
作用域用 host 丢了端口，自建 :8443 的 token 静默不发用源 URL 的 netloc 构造作用域
旧的 gcm.mirror hint 越过「关闭内置镜像」开关hint 必须仍在当前候选集合

另修：关闭预设后旧 origin 不自愈、安全断言被弱化（endswith(".extraHeader") 连旧实现都能通过）、 hint 预取不探测会白等 180s。镜像命令统一加 -c http.extraHeader=，实测能清除仓库级/全局认证头。

四、顺手修掉的真问题

问题根因证据
